Okteto runs on ARM-based Kubernetes clusters. On ARM, developers build and test on the same architecture as the operational clusters that run their application, which avoids the compatibility differences that appear when you develop on a different architecture.

## Support Status

| Cloud Provider | Recommended Instance | Status |
|---|---|---|
| Google GKE | Tau T2A (`t2a-standard-4`) | GA |
| Amazon EKS | Graviton 2/3 (`m7g.xlarge`) | Beta |

ARM goes through the same release pipeline as x86, and every control plane image is published as multi-arch (amd64 + arm64).

:::note
ARM support is available for **Self-Hosted deployments only**. Bring Your Own Cloud (BYOC) and SaaS deployments are not supported.
:::

## Requirements

- **Fresh installations only.** Migrating an existing x86 cluster to ARM isn't supported. You provision ARM clusters from scratch.
- **Homogeneous clusters.** Every node in the cluster must be ARM-based. Mixed architecture clusters (ARM + x86 nodes) aren't supported.

## Google GKE (GA)

ARM support on GCP with Tau T2A instances is generally available. Automated tests run against ARM clusters on GCP for every release, and in weekly scheduled runs.

### Cluster Configuration

Create a GKE cluster with Tau T2A nodes. We recommend the `t2a-standard-4` instance type:

```bash
gcloud container clusters create CLUSTER_NAME \
  --zone ZONE \
  --machine-type=t2a-standard-4 \
  --num-nodes=3 \
  --disk-size=250
```

:::note
Tau T2A instances are only available in some GCP regions and zones. The [GCP documentation](https://cloud.google.com/compute/docs/general-purpose-machines#t2a_machines) lists their regional availability.
:::

### Helm Configuration

GKE automatically applies `kubernetes.io/arch=arm64:NoSchedule` taints to ARM nodes. Add the following tolerations to your `config.yaml` so the Okteto components can be scheduled on those nodes:

```yaml
globals:
  tolerations:
    okteto:
      - key: "kubernetes.io/arch"
        operator: "Equal"
        value: "arm64"
        effect: "NoSchedule"
    dev:
      - key: "kubernetes.io/arch"
        operator: "Equal"
        value: "arm64"
        effect: "NoSchedule"
ingress-nginx:
  controller:
    tolerations:
      - key: "kubernetes.io/arch"
        operator: "Equal"
        value: "arm64"
        effect: "NoSchedule"
okteto-nginx:
  controller:
    tolerations:
      - key: "kubernetes.io/arch"
        operator: "Equal"
        value: "arm64"
        effect: "NoSchedule"
reloader:
  reloader:
    deployment:
      tolerations:
        - key: "kubernetes.io/arch"
          operator: "Equal"
          value: "arm64"
          effect: "NoSchedule"
```

The [GKE installation guide](get-started/install/google-gke.mdx) has the full installation steps.

## Amazon EKS (Beta)

:::warning Beta
ARM support on Amazon EKS is in **Beta**. The functionality is complete, but automated test coverage on EKS ARM is still maturing — validation is performed manually when introducing support for new Kubernetes versions. Until coverage matures, running this on operational clusters carries a higher chance of encountering an unexpected issue.
:::

AWS Graviton 2 and Graviton 3 instances are supported. The recommended instance type is `m7g.xlarge`, which is equivalent in size to the standard `m5.xlarge` used in the default EKS guide.

### Cluster Configuration

```bash
eksctl create cluster -f - <<EOF
apiVersion: eksctl.io/v1alpha5
kind: ClusterConfig

metadata:
  name: ${CLUSTER_NAME}
  region: ${AWS_REGION}
  version: "${K8S_VERSION}"

autoModeConfig:
  enabled: false

iam:
  withOIDC: true

nodeGroups:
  - name: ng-1
    instanceType: m7g.xlarge
    desiredCapacity: 3
    volumeSize: 250
    volumeType: gp3
    amiFamily: AmazonLinux2023
EOF
```

### Helm Configuration

EKS doesn't apply architecture taints to Graviton nodes, so ARM scheduling doesn't need additional tolerations.

The [Amazon EKS installation guide](get-started/install/amazon-eks.mdx) has the full installation steps.

## Dependencies

The following dependencies bundled in the Okteto Helm chart are validated for ARM compatibility:

- **Reloader**
- **Redis**
- **ingress-nginx**

## Limitations

The following scenarios are not supported in the current release:

| Scenario | Notes |
|---|---|
| Migration from x86 clusters | No migration tooling; fresh install required |
| Mixed architecture clusters | All nodes must be the same architecture |
| BYOC deployments | Not supported |
| Azure AKS ARM | Not supported |
| GCP Axion (C4A) instances | Not supported |
| Oracle Ampere A1/A2 | Not supported |
| Bare metal ARM | Not supported |
| Divert | Not supported on ARM (planned for a future release) |
| GPU workloads | The supported ARM instance types (Tau T2A, Graviton 2/3) don't offer GPUs |
| Windows containers | Not supported on ARM |
| WebAssembly (WASM) runtime | Not supported on ARM |
