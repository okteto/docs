**Admin > Catalog** lists the applications that Admins preconfigure for developers. Each Catalog item sets a repository, a branch, an Okteto Manifest path, and environment variables, so developers deploy an application environment from the Okteto UI without configuring any of them.

<Image
  src={require("@site/static/img/admin-catalog.png").default}
  alt="The Catalog section of the Admin Dashboard, with a table of Catalog items, their names and repository URLs, an Edit button on each row, and the Add Item button"
/>

Only Admins can manage the Catalog.

:::note
A **Read-only** tag next to a Catalog item means that the item is defined with a Custom Resource Definition (CRD). You can't change it from the Admin Dashboard: update its CRD instead, as [Catalog items in the CRDs reference](self-hosted/manage/crds.mdx#catalog-items) explains.
:::

## Creating the Catalog

You create and manage Catalog items in one of two ways:

1. [From the Admin Dashboard](#create-and-manage-catalog-items-via-the-dashboard)
1. [With Custom Resource Definitions (CRDs)](#create-and-manage-catalog-items-via-custom-resource-definitions-crds)

### Managing Catalog Items from the Admin Dashboard {#create-and-manage-catalog-items-via-the-dashboard}

Go to **Admin > Catalog** and click **Add Item** to open the **Add Catalog Item** form.

#### Adding an Application to the Catalog {#add-an-application-to-the-catalog}

The form adds a Catalog item: a preconfigured application that developers deploy with one click, from its repository and the settings you provide. It has these fields:

- **Name** (required)
- **Repository URL** (required)
- [**Default Branch**](#define-a-default-branch)
- [**Manifest Path**](#define-a-manifest-path)
- [**Environment Variables**](#add-environment-variables)

Fill in the ones you need and click **Save**.

  <Image
    src={require("@site/static/img/admin_catalog_view_add+1.33.png").default}

</p>

#### Default Branch {#define-a-default-branch}

**Default Branch** is the branch selected by default when a developer deploys the Catalog item.

You can add several Catalog items for the same **Repository URL**, each with a different **Default Branch**.

#### Manifest Path {#define-a-manifest-path}

**Manifest Path** is the path to your Okteto Manifest in the repository. It's optional.

#### Environment Variables {#add-environment-variables}

**Environment Variables** sets the variables that Okteto passes to every deployment of the Catalog item, so they're the same for every developer. They're optional. As with **Default Branch**, you can add several Catalog items for the same **Repository URL**, each with different environment variables.

### Managing Catalog Items with Custom Resource Definitions (CRDs) {#create-and-manage-catalog-items-via-custom-resource-definitions-crds}

You can also define Catalog items with [Custom Resource Definitions (CRDs)](self-hosted/manage/crds.mdx#catalog-items) and apply them to your cluster. This fits teams that work with GitOps or automate deployments with tools like `kubectl`, and it gives your instance a default Catalog from installation.

Catalog items defined with CRDs appear in the Okteto UI with the **Read-only** tag, and you can't change them from the Admin Dashboard. To manage a Catalog item from the UI, create it there instead.

The [CRDs reference](self-hosted/manage/crds.mdx#catalog-items) has the instructions and examples.

## Deploying from the Catalog {#deploy-a-dev-environment-from-your-catalog}

To deploy a Catalog item, go to **Namespaces**, click **Deploy Dev Environment**, and select **Catalog**.

The list shows every Catalog item. Select the one you want and click **Deploy**.
