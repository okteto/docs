Okteto pulls images from your private Amazon Elastic Container Registry (ECR) with the [Registry Credentials](admin/registry-credentials/index.mdx) you configure in the Admin Dashboard. ECR credentials can be the static credentials of an IAM user, or an IAM Role that Okteto assumes with a web identity through OIDC federation.

## Using IAM User Credentials

Configuring access to your private ECR with IAM user credentials takes three steps:

- Creating a user with access to your private ECR
- Getting the user's credentials
- Configuring the credentials in Okteto

### Step 1: Creating a user with access to your private ECR

The commands in this section use the [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html#getting-started-install-instructions).

Create an IAM user with the [AWS CLI](https://docs.aws.amazon.com/cli/latest/reference/iam/create-user.html) and give it read access to ECR:

```bash
aws iam create-user --user-name private-registry-user
```

```bash
aws iam attach-user-policy \
  --policy-arn arn:aws:iam::aws:policy/AmazonEC2ContainerRegistryReadOnly \
  --user-name private-registry-user
```

### Step 2: Getting the user's credentials

Create an access key for the IAM user with the [AWS CLI](https://docs.aws.amazon.com/cli/latest/reference/iam/create-access-key.html):

```bash
aws iam create-access-key --user-name private-registry-user
```

```yaml
{
    "AccessKey": {
        "UserName": "private-registry-user",
        "AccessKeyId": "<<your-access-key>>",
        "Status": "Active",
        "SecretAccessKey": "<<your-password>>",
        "CreateDate": "2023-10-10T09:08:27+00:00"
    }
}
```

Keep the values of `AccessKeyId` and `SecretAccessKey`: you enter them in Okteto in [Step 3: Configuring the credentials in Okteto](#step-3-configuring-the-credentials-in-okteto).

### Step 3: Configuring the credentials in Okteto

[Add a credential](admin/registry-credentials/index.mdx#adding-registry-credentials) in **Admin > Integrations > Registry Credentials** with these values:

- **Type**: `AWS IAM User`
- **Hostname**: your registry endpoint. The default one is `https://{AWS_ACCOUNT_ID}.dkr.ecr.{REGION}.amazonaws.com`
- **Access Key**: the `AccessKeyId` from [Step 2: Getting the user's credentials](#step-2-getting-the-users-credentials)
- **Secret Access Key**: the `SecretAccessKey` from [Step 2: Getting the user's credentials](#step-2-getting-the-users-credentials)

## Using IAM Roles via OpenID Connect (OIDC) Federation

Configuring access to your private ECR with an IAM Role through OpenID Connect (OIDC) federation takes three steps:

- Registering the identity provider
- Creating the IAM Role and granting it access to ECR
- Configuring the credentials in Okteto

### Step 1: Registering the Identity Provider

The commands in this section use the [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html#getting-started-install-instructions).

Register your Kubernetes cluster as an OIDC identity provider in AWS. To get your cluster's OIDC endpoint, click **Show Details** in the **OpenID Connect (OIDC)** row of [**Admin > Integrations > General**](admin/general-integrations.mdx#openid-connect-oidc):

<p align="left">
  <Image
    src={require("@site/static/img/amazon-ecr-oidc-config+1.32.png").default}
    alt="The OpenID Connect (OIDC) row of the General Integrations section of the Admin Dashboard, with the issuer and the subject"
    width="700"
  />
</p>

Store these values as environment variables for the next steps:

```bash
export OIDC_ENDPOINT=https://container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster
export OKTETO_SERVICE_ACCOUNT=system:serviceaccount:okteto:okteto
```

The `AUDIENCE` is usually the requester's client ID: AWS only exchanges tokens issued for this audience.
It's the `aud` field of the JWT payload. Use a different audience for each Okteto instance and AWS region, for example:

```bash
export AUDIENCE=okteto.example.com/us-east-2
```

Create the OIDC identity provider in AWS:

```bash
aws iam create-open-id-connect-provider --url "${OIDC_ENDPOINT}" --client-id-list "${AUDIENCE}"
```

The response looks like this:

```yaml
{
    "OpenIDConnectProviderArn": "arn:aws:iam::112233445566:oidc-provider/container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster"
}
```

Store this value in an environment variable for the next step:

```bash
export ROLE_ARN=arn:aws:iam::112233445566:oidc-provider/container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster
```

### Step 2: Creating the IAM Role and Granting Access to ECR

Create an IAM Role with access to ECR that the OIDC identity provider from [Step 1: Registering the Identity Provider](#step-1-registering-the-identity-provider) can assume.

First, create the trust policy that lets the OIDC identity provider assume the IAM Role.
Save this content to a file named `trust-policy.json`, replacing the environment variables with their values:

```yaml title="trust-policy.json"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "${ROLE_ARN}"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "${OIDC_ENDPOINT}:aud": "${AUDIENCE}",
          "${OIDC_ENDPOINT}:sub": "${OKTETO_SERVICE_ACCOUNT}"
        }
      }
    }
  ]
}
```

Create the IAM Role in AWS with your trust policy:

```bash
aws iam create-role --role-name my-private-registry --assume-role-policy-document file://trust-policy.json
```

The response looks like this:

```yaml
{
    "Role": {
        "Path": "/",
        "RoleName": "my-private-registry",
        "RoleId": "AR...",
        "Arn": "arn:aws:iam::112233445566:role/my-private-registry",
        "CreateDate": "2024-06-10T15:04:05+00:00",
        "AssumeRolePolicyDocument": {
            "Version": "2012-10-17",
            "Statement": [
                {
                    "Effect": "Allow",
                    "Principal": {
                        "Service": "ec2.amazonaws.com"
                    },
                    "Action": "sts:AssumeRole"
                }
            ]
        }
    }
}
```

Attach an ECR policy that allows the IAM Role to pull from the registry:

```bash
aws iam attach-role-policy --role-name my-private-registry --policy-arn arn:aws:iam::aws:policy/AmazonEC2ContainerRegistryReadOnly
```

### Step 3: Configuring the credentials in Okteto

Go to **Admin > Integrations > Registry Credentials**, click **Add Credential**, and enter these values, as [Adding Registry Credentials](admin/registry-credentials/index.mdx#adding-registry-credentials) explains:

- **Type**: `AWS IAM Role (via OIDC)`
- **Hostname**: your ECR registry endpoint, `https://{AWS_ACCOUNT_ID}.dkr.ecr.{REGION}.amazonaws.com`
- **Role ARN**: the Role ARN `ROLE_ARN` from [Step 1: Registering the Identity Provider](#step-1-registering-the-identity-provider)
- **Audience JWT Claim**: the `AUDIENCE` you set when you registered the identity provider

:::tip
You can also configure these credentials with [Kubernetes CRDs](self-hosted/manage/crds.mdx#private-registries), to automate the configuration of your Okteto instance (for example, with infrastructure as code in Terraform, or GitOps with Argo CD).
:::
