AWS Cloud Credentials give the `deploy`, `destroy`, and `test` commands in your Okteto Manifest access to your AWS account. Okteto uses [OIDC federation](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_providers_oidc.html) to [assume an IAM Role with a web identity](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_manage-assume.html), which gives the commands temporary access to your AWS resources.

:::info
Okteto injects Cloud Credentials only into the `deploy`, `destroy`, and `test` commands that it runs on the cluster. They aren't available inside a Development Container started with `okteto up`, or during image builds.
:::

This page grants access to S3 buckets. To grant access to other AWS resources, give the role the permissions they need.

## Step 1: Registering the Identity Provider

The commands on this page use the [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html#getting-started-install-instructions).

Register your Kubernetes cluster as an OIDC identity provider in AWS. To get your cluster's OIDC issuer and subject, click **Show Details** in the **OpenID Connect (OIDC)** row of [**Admin > Integrations > General**](admin/integrations.mdx#openid-connect-oidc):

<p align="center">
  <Image
    src={require("@site/static/img/amazon-ecr-oidc-config+1.32.png").default}
    alt="The OpenID Connect (OIDC) row of the General Integrations section of the Admin Dashboard, with the issuer and the subject"
  />
</p>

Store the values as environment variables for the next steps:

```bash
export OIDC_ISSUER=https://container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster
export OIDC_SUBJECT=system:serviceaccount:okteto:okteto
```

Next, define the `AUDIENCE`.
The `AUDIENCE` is usually the requester's client ID: AWS only exchanges tokens issued for this audience.
It's the `aud` field of the JWT payload. Use a different audience for each Okteto instance and AWS region, for example:

```bash
export AUDIENCE=okteto.example.com/us-east-2
```

Create the OIDC identity provider in AWS:

```bash
aws iam create-open-id-connect-provider --url "${OIDC_ISSUER}" --client-id-list "${AUDIENCE}"
```

The response includes the provider ARN:

```yaml
{
    "OpenIDConnectProviderArn": "arn:aws:iam::112233445566:oidc-provider/container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster"
}
```

Store this value in an environment variable for the next step:

```bash
export PROVIDER_ARN=arn:aws:iam::112233445566:oidc-provider/container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster
```

## Step 2: Creating the IAM Role and Granting Access to S3

Create an IAM Role with access to S3 that the OIDC identity provider from [Step 1: Registering the Identity Provider](#step-1-registering-the-identity-provider) can assume.

### Creating the Trust Policy

First, create the trust policy that lets the OIDC identity provider assume the role. Create a local file named `trust-policy.json` with this content, and replace the placeholders with the values from [Step 1: Registering the Identity Provider](#step-1-registering-the-identity-provider):


```yaml title="trust-policy.json"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "<PROVIDER_ARN>"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "<OIDC_ISSUER>:aud": "<AUDIENCE>",
          "<OIDC_ISSUER>:sub": "<OIDC_SUBJECT>"
        }
      }
    }
  ]
}
```

The placeholders are:

- **OIDC_ISSUER**: your Okteto instance's OIDC issuer, `OIDC_ISSUER`, without the `https://` prefix.
- **OIDC_SUBJECT**: your Okteto instance's OIDC subject, `OIDC_SUBJECT`.
- **AUDIENCE**: the audience you defined, `AUDIENCE`.
- **PROVIDER_ARN**: the OpenID Connect provider's ARN, `PROVIDER_ARN`.

A completed file looks like this:

```yaml title="trust-policy.json"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::112233445566:oidc-provider/container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster:aud": "okteto.example.com/us-east-2",
          "container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster:sub": "system:serviceaccount:okteto:okteto"
        }
      }
    }
  ]
}
```

Create the IAM Role in AWS with your trust policy:

```bash
aws iam create-role --role-name okteto-credentials --assume-role-policy-document file://trust-policy.json
```

The response looks like this:

```yaml
{
    "Role": {
        "Path": "/",
        "RoleName": "okteto-credentials",
        "RoleId": "AR...",
        "Arn": "arn:aws:iam::112233445566:role/okteto-credentials",
        "CreateDate": "2024-06-10T15:04:05+00:00",
        "AssumeRolePolicyDocument": {
            "Version": "2012-10-17",
            "Statement": [
                {
                    "Effect": "Allow",
                    "Principal": {
                         "Federated": "arn:aws:iam::112233445566:oidc-provider/container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster"
                    },
                    "Action": "sts:AssumeRoleWithWebIdentity",
                    "Condition": {
                        "StringEquals": {
                            "container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster:aud": "okteto.example.com/us-east-2",
                            "container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster:sub": "system:serviceaccount:okteto:okteto"
                        }
                    }
                }
            ]
        }
    }
}
```

Store the new role's `ARN` in an environment variable for the next step:

```bash
export ROLE_ARN=arn:aws:iam::112233445566:role/okteto-credentials
```

Finally, attach the S3 policy to the IAM Role, which grants it full read and write access to your S3 buckets:

```bash
aws iam attach-role-policy --role-name okteto-credentials --policy-arn arn:aws:iam::aws:policy/AmazonS3FullAccess
```

## Step 3: Configuring AWS Cloud Credentials in Okteto

You can configure Cloud Credentials in two ways:

- **In the Admin Dashboard**, as [Adding Cloud Credentials Through the Admin Dashboard](#adding-cloud-credentials-through-the-admin-dashboard) explains.
- **With a CRD**, as [Cloud Credentials CRDs](self-hosted/manage/crds.mdx#cloud-credentials) explains.

:::note
The Admin Dashboard shows the credentials you add with CRDs, but you can't change them from the Admin Dashboard.
:::

### Adding Cloud Credentials Through the Admin Dashboard

1. Go to [**Admin > Integrations > Cloud Credentials**](admin/cloud-credentials/index.mdx).
2. Click **Enable** in the **AWS IAM Role** row.
  <p align="center">
    <Image
      src={require("@site/static/img/aws-cloud-credentials+1.32.png").default}
      alt="The AWS IAM Role row of the Cloud Credentials section of the Admin Dashboard, disabled, with an Enable button"
    />
  </p>
3. Enter these values:

- **Role ARN**: the `ROLE_ARN` you stored in [Step 2: Creating the IAM Role and Granting Access to S3](#step-2-creating-the-iam-role-and-granting-access-to-s3).
- **Region**: the AWS Region for the AWS STS regional endpoint. See [AWS STS Regions](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_temp_enable-regions.html) and [STS regionalized endpoints](https://docs.aws.amazon.com/sdkref/latest/guide/feature-sts-regionalized-endpoints.html).
- **Audience JWT Claim**: the `AUDIENCE` you defined in [Step 1: Registering the Identity Provider](#step-1-registering-the-identity-provider).

The `deploy`, `destroy`, and `test` commands in your Okteto Manifest then have access to your AWS account.

## Example Okteto Manifest

With AWS Cloud Credentials enabled, this Okteto Manifest creates, lists, and deletes an S3 bucket:

```yaml
deploy:
  image: amazon/aws-cli
  commands:
    - aws s3 mb s3://test-bucket --region us-west-2

test:
  aws:
    image: amazon/aws-cli
    commands:
      - aws s3 ls | grep test-bucket

destroy:
  image: amazon/aws-cli
  commands:
    - aws s3 rb s3://test-bucket --region us-west-2
```
