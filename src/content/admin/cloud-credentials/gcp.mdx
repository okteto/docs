Google Cloud Platform (GCP) Cloud Credentials give the commands in your Okteto Manifests access to your GCP account. Okteto uses [Workload Identity Federation](https://cloud.google.com/iam/docs/workload-identity-federation), which gives the commands temporary access to your GCP resources.

This page grants access to Cloud Storage. To grant access to other GCP resources, bind a role with the permissions they need.

## Step 1: Creating the Workload Identity Pool

:::info
The commands on this page use the [Google Cloud CLI](https://cloud.google.com/sdk/docs/install).
:::

A Workload Identity Pool is a group of identities that can access GCP resources.

Choose a name for your Workload Identity Pool and export it as an environment variable:

```bash
export POOL_ID=okteto-pool
```

Create the Workload Identity Pool:

```bash
gcloud iam workload-identity-pools create ${POOL_ID} --location=global --display-name="Okteto pool"
```

## Step 2: Registering the OIDC Identity Provider

Register your Kubernetes cluster as an OIDC identity provider in the new Workload Identity Pool. To get your cluster's OIDC endpoint, click **Show Details** in the **OpenID Connect (OIDC)** row of [**Admin > Integrations > General**](admin/integrations.mdx#openid-connect-oidc):

<p align="center">
  <Image
    src={require("@site/static/img/amazon-ecr-oidc-config+1.32.png").default}
    alt="The OpenID Connect (OIDC) row of the General Integrations section of the Admin Dashboard, with the issuer and the subject"
  />
</p>

Store these values as environment variables for the next steps:

```bash
export OIDC_ENDPOINT=https://container.googleapis.com/v1/projects/myProject/locations/us-central1/clusters/myCluster
export OKTETO_SERVICE_ACCOUNT=system:serviceaccount:okteto:okteto
```

The `AUDIENCE` is usually the requester's client ID: GCP only exchanges tokens issued for this audience.
It's the `aud` field of the JWT payload. Use a different audience for each Okteto instance and GCP region, for example:

```bash
export AUDIENCE=okteto.example.com/us-central1
```

Create the identity provider:

```bash
gcloud iam workload-identity-pools providers create-oidc myCluster \
  --location=global \
  --workload-identity-pool=${POOL_ID} \
  --display-name="Okteto Identity Provider" \
  --attribute-mapping="google.subject=assertion.sub" \
  --issuer-uri="${OIDC_ENDPOINT}" \
  --allowed-audiences=${AUDIENCE}
```

## Step 3: Creating the IAM Policy Binding

Grant the Okteto Kubernetes service account the permissions it needs to access your GCP resources.

First, get your Google Cloud project's `PROJECT_ID` and `PROJECT_NUMBER` from its [settings in the Google Cloud console](https://console.cloud.google.com/iam-admin/settings).

Set these variables:

```bash
export PROJECT_ID=myProject-123
export PROJECT_NUMBER=118593354781
export PRINCIPAL=iam.googleapis.com/projects/${PROJECT_NUMBER}/locations/global/workloadIdentityPools/${POOL_ID}/subject/${OKTETO_SERVICE_ACCOUNT}
```

Bind the IAM role to the service account:

```bash
gcloud projects add-iam-policy-binding ${PROJECT_ID} --role=roles/storage.admin --member=principal://${PRINCIPAL} --condition=None
```

The binding gives the Okteto service account access to Cloud Storage.

## Step 4: Configuring GCP Cloud Credentials in Okteto

You can configure Cloud Credentials in two ways:

- **In the Admin Dashboard**, as [Adding Cloud Credentials Through the Admin Dashboard](#adding-cloud-credentials-through-the-admin-dashboard) explains.
- **With a CRD**, as [Cloud Credentials CRDs](self-hosted/manage/crds.mdx#cloud-credentials) explains.

:::note
The Admin Dashboard shows the credentials you add with CRDs, but you can't change them from the Admin Dashboard.
:::

### Adding Cloud Credentials Through the Admin Dashboard

Go to [**Admin > Integrations > Cloud Credentials**](admin/cloud-credentials/index.mdx) and click **Enable** in the **GCP Workload ID** row:

<p align="center">
  <Image
    src={require("@site/static/img/gcp-cloud-credentials+1.32.png").default}
    alt="The GCP Workload ID row of the Cloud Credentials section of the Admin Dashboard, disabled, with an Enable button"
  />
</p>

Enter these values:

- **Project Number**: the `PROJECT_NUMBER` of the GCP project where your resources are.
- **Workload Identity Pool ID**: the `POOL_ID` you created in [Step 1: Creating the Workload Identity Pool](#step-1-creating-the-workload-identity-pool).
- **Provider ID**: the ID of the OIDC provider you created in [Step 2: Registering the OIDC Identity Provider](#step-2-registering-the-oidc-identity-provider).
- **Audience JWT Claim**: the `AUDIENCE` you set when you registered the identity provider.

## Example Okteto Manifest

With GCP Cloud Credentials enabled, this Okteto Manifest creates, lists, and deletes a storage bucket:

```yaml
deploy:
  image: gcr.io/google.com/cloudsdktool/google-cloud-cli:stable
  commands:
    - gcloud storage buckets create gs://test-bucket

test:
  gcp:
    image: gcr.io/google.com/cloudsdktool/google-cloud-cli:stable
    commands:
      - gcloud storage ls | grep test-bucket

destroy:
  image: gcr.io/google.com/cloudsdktool/google-cloud-cli:stable
  commands:
    - gcloud storage buckets delete gs://test-bucket
```
