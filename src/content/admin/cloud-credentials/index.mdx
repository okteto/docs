**Admin > Integrations > Cloud Credentials** gives the `deploy`, `destroy`, and `test` commands of your Okteto Manifests access to your cloud provider account. Okteto uses your Okteto cluster's identity, so neither you nor your developers manage static credentials: once you configure Cloud Credentials, every developer's commands can access your cloud provider.

<Image
  src={require("@site/static/img/admin-cloud-credentials.png").default}
  alt="The Cloud Credentials section of the Admin Dashboard, with the AWS IAM Role, GCP Workload ID, and Azure Workload ID providers, each enabled or disabled"
/>

Each cloud provider has its own row: **AWS IAM Role**, **GCP Workload ID**, and **Azure Workload ID**. Click **Enable** to configure a provider, **Edit** to change its configuration, and **Disable** to remove it. Disabling a provider deletes its configuration.

These guides explain how to configure Cloud Credentials for each cloud provider:

- [Amazon Web Services](admin/cloud-credentials/aws.mdx)
- [Google Cloud](admin/cloud-credentials/gcp.mdx)
- [Microsoft Azure](admin/cloud-credentials/azure.mdx)

:::note
A **Read-only** tag next to a provider means that its Cloud Credentials were defined with a Custom Resource Definition (CRD). You can't change them from the Admin Dashboard: click **Show** to see their values, and [update the associated CRD](self-hosted/manage/crds.mdx#cloud-credentials) to change them.
:::
