The Okteto Resource Manager sets the CPU and memory requests of your Kubernetes workloads on Okteto from their actual usage, so nobody has to tune them by hand. **Admin > Resource Manager** sets whether it applies its recommendations automatically, and shows your pods' average CPU and memory usage next to their requests.

## Benefits

Configuring CPU and memory requests in Kubernetes by hand is tedious, and it's easy to get wrong.
Wrong requests lead to poor performance, overloaded nodes, and slow application environments.
The Resource Manager adjusts the requests from the cluster's usage data, so your pods get the resources they use and your nodes stay balanced.

- **Less configuration work**: Developers don't manage requests in Kubernetes, and focus on their code.
- **Right-sized requests**: Requests match actual usage, so you don't waste resources or starve your pods.
- **Faster application environments**: Developers get better performance from their application environments.
- **Lower costs**: Nobody spends time configuring resources by hand.

## How it Works

The Resource Manager monitors the CPU and memory usage of your pods over time.
It calculates their average usage and adjusts the requests of new pods to it, in these steps:

1. **Data Collection**: The Resource Manager queries the Kubernetes Metric Server for the CPU and memory usage of every pod that Okteto manages. The Resource Manager requires the Kubernetes Metric Server.
1. **Average Calculation**: It calculates the average CPU and memory usage of each container family (grouped by application environment, controller name, and container name).
1. **Recommendation Generation**: It generates new resource requests from the average usage, with a correction factor.
1. **Automatic Application**: When Okteto creates a new pod, it applies the recommended requests, unless the pod has the annotation `dev.okteto.com/resource-manager: false`.
1. **Data lifecycle**: The Resource Manager stores only a running average for each container family, in Redis (with persistence disabled). It doesn't keep any history. If Redis is cleared, the next scheduled run (every 5 minutes by default) calculates the averages again. You can [change how often it runs in the Helm chart](self-hosted/helm-configuration.mdx#resourcemanager).

## Configuring the Resource Manager

### Enabling the Resource Manager

The Resource Manager is available in Okteto chart version 1.26 and later. The [Helm configuration reference](self-hosted/helm-configuration.mdx#resourcemanager) lists its options.

#### Enabling It in the Helm Chart

1. Update and deploy your [Helm chart with the Resource Manager configuration](self-hosted/helm-configuration.mdx#resourcemanager), with the changes that your cluster needs.
1. Once it's enabled, the Resource Manager starts a cron job every 5 minutes to calculate the recommendations.

#### Turning On Automatic Recommendations

1. Log in to the Okteto UI as an Admin.
1. Go to **Admin > Resource Manager**, in the Settings group.
1. If the Resource Manager is enabled, you see the **Manual** and **Automatic** options. The default is **Automatic**.
1. Select **Automatic**.

In **Automatic** mode, the Resource Manager adjusts resource requests to the average usage.

### Customizing Resource Manager Settings

You customize the Resource Manager with its settings in your Helm configuration. The [Helm reference](self-hosted/helm-configuration.mdx#resourcemanager) lists them all.

:::info
In **Automatic** mode, the Resource Manager's recommendations override the CPU and memory requests that users define.
:::

## Viewing Resource Metrics and Recommendations

### Resource Metrics View

The Resource Manager adds a **Metrics** tab to the Namespace view of the Okteto UI. It shows the resource usage and performance of your Kubernetes workloads.
The tab is available for Deployments, StatefulSets, Jobs, CronJobs, and Pods.

The [Namespaces documentation](core/namespaces.mdx#resource-metrics-view) lists the available metrics.

## Excluding Resources

If the Resource Manager's recommendations don't suit a component, you can exclude it from the Resource Manager.

Add the annotation `dev.okteto.com/resource-manager` with the value `false` to your pod's metadata to prevent automatic adjustments.

Example of a Kubernetes manifest:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello-world
spec:
  selector:
    matchLabels:
      app: hello-world
  template:
    metadata:
      annotations:
        dev.okteto.com/resource-manager: "false"
```

Example of a Docker Compose file:

```yaml
services:
  hello-world:
    labels:
      dev.okteto.com/resource-manager: "false"
```

Okteto translates Docker Compose labels to Kubernetes annotations.

## Disabling the Resource Manager

To stop the Resource Manager's automatic adjustments for a while, select **Manual** in **Admin > Resource Manager**.
{/* - To uninstall Resource Manager, you can set the `resourceManager` helm setting to `enabled: false` */}

## Troubleshooting and Support

### Metric Server Availability

The Resource Manager relies on the Kubernetes Metric Server. If the Metric Server is unavailable, the Okteto UI shows an error message. To troubleshoot it, see the [Kubernetes documentation for the Metrics Server](https://kubernetes.io/docs/tasks/debug/debug-cluster/resource-metrics-pipeline/#metrics-server).

### Known Limitation: Support for ReplicaSet and CronJob

The Resource Manager doesn't optimize ReplicaSets and CronJobs by default, because of technical limitations. To turn on its optimizations for a ReplicaSet or a CronJob, add the label `dev.okteto.com/component-name` to it.

Example of a CronJob manifest with the `dev.okteto.com/component-name` label:

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: hello-world
spec:
  schedule: "* * * * *"
  jobTemplate:
    spec:
      template:
        metadata:
          labels:
            dev.okteto.com/component-name: "hello-world"
```
