**Admin > Nodes** shows each node of your Kubernetes cluster with its CPU usage, memory usage, and number of pods, compared with the node's capacity. When warm nodes are enabled, Admins also set the number of warm nodes there, and the table marks which nodes are warm.

## Warm Nodes

Warm nodes are nodes for your application environments that Okteto keeps ready, with the Okteto images and the extra images you configure already pulled. When a pod in a Namespace doesn't fit on any other node, Kubernetes runs it on a warm node, so it starts without waiting for those images to download. The cluster autoscaler then adds a new node to replace the warm node. Each warm node is an idle node, which adds to your infrastructure costs.

Warm nodes are disabled by default, and **Admin > Nodes** shows the **Warm Nodes** setting only when they're enabled. To enable them, and for their requirements, see [`warmNodes`](self-hosted/helm-configuration.mdx#warmnodes) in the Helm configuration.

### Setting the Number of Warm Nodes

1. Open **Admin > Nodes**.
2. In **Warm Nodes**, enter the number of nodes to keep warm, from 0 to 20.
3. Click **Save**.

Okteto adds or removes warm nodes to match the number. A new warm node takes some time to be ready: the cluster autoscaler adds the node, and the node pulls the images. Set the number to 0 to stop keeping warm nodes without disabling them.

If the number was set above 20 outside of the Admin Dashboard, for example with `kubectl scale`, **Admin > Nodes** shows it with a warning. You can only save a number up to 20.

### Read-Only Number of Warm Nodes

When the [`warmNodes.countManagedExternally`](self-hosted/helm-configuration.mdx#warmnodes) Helm setting is `true`, you set the number of warm nodes outside of Okteto, for example from your GitOps tool or [on a schedule](#warm-nodes-on-a-schedule). **Admin > Nodes** shows the number with the **Read-only** tag, and without the **Save** button.

### Warm Nodes on a Schedule

The number of warm nodes is the number of replicas of the `okteto-warm-nodes` Deployment, in the `okteto` namespace. To change it on a schedule, for example to keep warm nodes during working hours and none at night or on weekends, set the `warmNodes.countManagedExternally` Helm setting to `true` and scale the Deployment from a tool that runs on a schedule. Okteto upgrades never change the number of replicas of the Deployment, and **Admin > Nodes** doesn't change it while it's read-only, so Okteto doesn't overwrite the scheduled changes. The maximum of 20 warm nodes only applies to **Admin > Nodes**.

Don't scale the Deployment with an autoscaler based on resource usage, such as a HorizontalPodAutoscaler on CPU or memory: the warm pods use almost no CPU or memory, whether your cluster needs their nodes or not.

For example, with [KEDA](https://keda.sh) installed in your cluster, this `ScaledObject` keeps 5 warm nodes from 8:00 to 19:00 on weekdays, and none the rest of the time:

```yaml
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: okteto-warm-nodes
  namespace: okteto
spec:
  scaleTargetRef:
    name: okteto-warm-nodes
  minReplicaCount: 0
  maxReplicaCount: 5
  triggers:
    - type: cron
      metadata:
        timezone: America/New_York
        start: 0 8 * * 1-5
        end: 0 19 * * 1-5
        desiredReplicas: "5"
```

Outside the schedule, KEDA scales the Deployment to 0, so Okteto keeps no warm nodes. Without KEDA, a Kubernetes CronJob that runs `kubectl scale deployment okteto-warm-nodes --replicas=<number> --namespace=okteto` at the start and at the end of the working day does the same, with a ServiceAccount allowed to scale Deployments in the `okteto` namespace.

### Warm Tag

The table shows a **Warm** tag next to the name of each warm node. A node is warm while a warm pod runs on it, including while it's still pulling the images. When one of your pods takes a warm node, the node loses the tag, and the new warm node gets it once the cluster autoscaler adds it. If the cluster autoscaler can't add nodes, for example because the node pool is at its maximum size, the table shows fewer warm nodes than the number you set.
