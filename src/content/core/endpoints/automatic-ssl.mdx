Okteto exposes the applications deployed in your Namespaces on HTTPS endpoints. Okteto generates a hostname for each endpoint with the format `<name>-<namespace>.<okteto-subdomain>`, serves it over HTTPS, and shows it in the Okteto UI. The same manifests work in every Namespace, and hostnames stay the same across redeploys as long as the name of the resource doesn't change.

## Creating Endpoints

### HTTPRoutes

Define your own Gateway API HTTPRoutes. Okteto attaches them to its `Gateway` and generates their hostnames. See [Endpoints for HTTPRoutes](core/endpoints/httproutes.mdx).

### Docker Compose

Declare endpoints in your Docker Compose file, and Okteto creates an Ingress object or an HTTPRoute for each of them. See [Endpoints for Docker Compose](core/endpoints/docker-compose.mdx).

### Ingress

Define your own Ingress objects when you need several paths or specific routing rules. Okteto generates their hostnames for you. See [Endpoints for Ingress](core/endpoints/ingress.mdx).

### Services

Add the `dev.okteto.com/auto-ingress` annotation to a Service, and Okteto creates an endpoint for it. See [Endpoints for Services](core/endpoints/services.mdx).

### Custom Endpoints

Hide endpoints from the Okteto UI, or replace the endpoints it shows, with annotations. See [Custom Endpoints](core/endpoints/custom-endpoints.mdx).

If you've configured endpoints but they aren't appearing, check the [FAQ](reference/faqs.mdx#why-are-my-endpoints-not-present-in-the-cli-or-ui) for possible reasons.
