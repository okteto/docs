This page lists common Divert issues by symptom. For the cluster requirements, such as the service mesh, see [Configure Divert in Your Cluster](self-hosted/install/divert/index.mdx).

## Requests with My Divert Header Still Reach the Shared Environment

1. **Check the header format.** The header is `baggage: okteto-divert=<your-namespace>`. Formats like `baggage.okteto-divert: alice` or `okteto-divert: alice` don't work, and the value must match your Namespace name exactly.

2. **Check that the request reaches your service directly.** Call your diverted service through the shared endpoint with your divert header:

   ```bash
   curl -H "baggage: okteto-divert=alice" https://movies-movies-shared.okteto.example.com/api/catalog/healthz
   ```

   If this reaches your version but requests through the rest of the application don't, a service in the call chain isn't propagating the header. See [Header Propagation](development/divert/header-propagation.mdx#recognizing-the-problem).

3. **Check that Okteto created the routes for your services.** With the default driver, Okteto creates a Divert resource for each service you deploy, and a route named `okteto-<service>` in the shared environment:

   ```bash
   kubectl get diverts -n <your-namespace>
   kubectl get httproute -n <shared-namespace>
   ```

   If they are missing, ask your Admin to check the Divert configuration.

4. **Check the `divert` section of your Okteto Manifest.** `divert.namespace` must be the name of the shared environment.

## My Diverted Service Can't Reach a Shared Service

Your pods resolve service names to your Namespace first and to the shared environment if the service doesn't exist in your Namespace. Test the resolution from your pod:

```bash
kubectl exec -it deployment/<your-service> -n <your-namespace> -- nslookup catalog
```

- If the name doesn't resolve, check that the service exists in the shared environment and that `divert.namespace` points to it.
- If it resolves but the connection fails, network policies may block traffic between namespaces. Ask your Admin to allow it.
- If your service uses a fully qualified name, such as `catalog.staging.svc.cluster.local`, it always reaches that namespace, regardless of what you deploy.

## My Service Uses the Wrong Database or Broker

Short service names, like `postgresql` or `kafka`, resolve to your Namespace if you deployed that service, and to the shared environment if you didn't. Check which one your service connects to:

```bash
kubectl get services -n <your-namespace>
```

- If you deployed a database or broker but your service connects to the shared one, check that the connection string uses the short name, not a fully qualified name.
- If you didn't mean to deploy a database or broker, check for `depends_on` entries in your Docker Compose file, which make Okteto deploy those services in your Namespace.

See [Data Cloning](development/divert/data-cloning.mdx) and [Queue Splitting](development/divert/queue-splitting.mdx).

## My Consumer Doesn't Receive Its Messages

1. **Check that the producer copies the divert header.** Inspect a message in your broker's console and check that it has a `baggage` header (Kafka, RabbitMQ) or an `okteto-divert` attribute (SQS).
2. **Check that the producer received the divert header.** If the producer runs in the shared environment, the request that triggered the message must carry your divert header.
3. **Check the consumer group.** With Kafka, your consumer and the shared consumer need different consumer groups. With the same group, Kafka delivers each message to only one of them.
4. **Check `OKTETO_DIVERTED_ENVIRONMENT`.** It must be set in your consumer and match your Namespace name:

   ```bash
   kubectl exec deployment/<your-consumer> -n <your-namespace> -- env | grep OKTETO_
   ```

## Requests from the Frontend Don't Reach My Backend

If the frontend runs in the shared environment, the JavaScript in your browser calls the shared environment's API hosts. Those calls only carry your divert header if your browser adds it. Send the header from your browser with an extension such as [ModHeader](https://modheader.com/).

## My Diverted Environment Doesn't Wake Up

Requests routed from the shared environment don't wake up a sleeping diverted environment. Wake it up from the Okteto UI before sending requests to it.
