Okteto deploys application environments from private Git repositories: from GitHub through the GitHub integration, and from any other Git provider over SSH.

## GitHub Private Repositories

With the GitHub integration, you can deploy any repository from the accounts and organizations that you grant permissions to. You can connect your personal repositories and your organizations' repositories to the same Okteto account.

:::note
An Admin must enable the GitHub integration for your instance before you can connect your GitHub account. If the **Deploy** dialog doesn't offer **GitHub** as a source, ask your Admin to [set up the GitHub integration](self-hosted/install/github.mdx).
:::

### Connecting Your GitHub Account

You connect your GitHub account once: Okteto keeps your GitHub permissions across sessions.

1. Log in to your Okteto instance.
1. Click **Deploy Dev Environment** at the top.
1. Make sure **GitHub** is the selected source.
1. Click **Configure GitHub** or **Add repositories** to open GitHub's authorization dialog. GitHub asks you to install the Okteto App in the accounts and organizations you select. Follow the instructions to grant permissions to your repositories.

   <p align="center">

       src={require("@site/static/img/private-repositories-enable.png").default}

       width="400"
     />
   </p>

1. Click **Install & Authorize**. If you aren't an administrator of the organization, GitHub emails your administrator and waits for their approval to complete the installation and grant you access.

Once you or your GitHub administrator grants permission, the **Deploy** dialog lists your public and private repositories. A lock icon on the right marks the private ones.

### Adding or Removing Repositories

To change the repositories that Okteto can access, go to **Settings > Integrations** and click **Configure GitHub**. GitHub opens a dialog where you add or remove repositories from any organization that you belong to.

<p align="left"><Image src={require('@site/static/img/private-repositories-update-sidebar+1.32.png').default} alt="The Integrations page of the Okteto Settings, with the Configure GitHub button" /></p>

If you select repositories from an organization or a user account other than the one that owns the GitHub App, GitHub asks you to install the app in that organization. Only the organization's administrators can install it.

Even if an organization grants Okteto access to all its repositories, each developer only sees the repositories that they can access in GitHub.

### Deploying from a Private GitHub Repository

After you connect your GitHub account, you can deploy any of your public or private repositories [with an Okteto Manifest](reference/okteto-manifest.mdx).

## Other Private Repositories

Okteto also deploys private repositories with SSH authentication. Use your Git repository's SSH URL, both in the [**Deploy**](development/deploy/deploy-from-git.mdx) dialog of the Okteto UI and with the [`okteto pipeline deploy`](reference/okteto-cli.mdx#deploy) command in your terminal.

<p align="center">
  <Image
    src={require("@site/static/img/private-repository+1.42.png").default}
    alt="Deploy Dev Environment dialog with Git URL source selected and an SSH repository URL entered"
    width="676"
  />
</p>

To let Okteto clone the repository over SSH, an Admin adds the [Okteto SSH key](admin/general-integrations.mdx#git-ssh-key) to your source code provider.

:::note
Admins manage the trusted SSH hosts of every Git provider (GitHub, GitLab, Bitbucket, Azure DevOps, or self-hosted) in one place: [SSH Known Hosts](admin/ssh-known-hosts.mdx). Trusted hosts avoid host key verification failures in remote deploys and submodule operations.
:::
