File Sync keeps your local files and your Development Container in sync while `okteto up` runs. When you start `okteto up`, the Okteto CLI starts [Syncthing](https://syncthing.net/) on your machine and in the Development Container, and Syncthing copies every change in both directions.

## Synchronization Status

Syncthing has a web UI that shows the state of the synchronization. To get the Syncthing URLs and credentials of your Development Container, run `okteto status --info` while `okteto up` runs:

```bash
okteto status --info
```

```console
 i  Local syncthing url: http://localhost:60539
 i  Remote syncthing url: http://localhost:60538
 i  Syncthing username: okteto
 i  Syncthing password: ac0ee34a-b1aa-4a41-bc67-cec3128b6cfd
 ✓  Synchronization status: 100.00%
```

## Ignoring Files

To keep files out of the synchronization, add a `.stignore` file to the root of the folder that you synchronize, with one file or path pattern per line. The patterns follow the syntax of `.gitignore` and `.dockerignore`, and the first pattern that matches a file decides whether Syncthing ignores it. See [Syncthing's ignore syntax](https://docs.syncthing.net/users/ignoring.html) for every option.

For example, a `.stignore` file for a Go project:

```text title=".stignore"
okteto.yaml
.git
*.exe
*.exe~
*.dll
*.so
*.dylib

# Test binary, built with go test -c
*.test

# Output of the go coverage tool
*.out
```

:::tip
Set the `OKTETO_AUTOGENERATE_STIGNORE` [feature flag](reference/feature-flags.mdx) to `true`, and `okteto up` generates a default `.stignore` file for your programming language.
:::

## Hot Reload and File Watchers

If the hot reloader in your Development Container doesn't pick up your changes, even though File Sync copies them, the limit of inotify file watchers on your Kubernetes nodes is usually too low. `okteto up` warns you when the value of `/proc/sys/fs/inotify/max_user_watches` on the node is too low.

Okteto raises this limit on every node by default, with the [`overrideFileWatchers`](self-hosted/helm-configuration.mdx#overridefilewatchers) Helm setting. If an Admin disabled that setting, set the limit on each node:

```bash
sudo sysctl -w fs.inotify.max_user_watches=10048576
```
