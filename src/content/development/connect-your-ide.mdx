`okteto up` runs an [SSH server](application-environments/develop/index.mdx#ssh-server) in your Development Container, and any IDE with remote development over SSH, such as Visual Studio Code or the JetBrains IDEs, can open a project through it. With a remote IDE, the code can live only in the Development Container: you clone the repository there instead of synchronizing it from your machine, so the IDE's Git integration, language server, terminal, and debugger all work against the same copy. This example creates a Development Container for that, clones [okteto/go-getting-started](https://github.com/okteto/go-getting-started) into it, and deploys the application from inside the container.

## Prerequisites

Install the [Okteto CLI](get-started/install-okteto-cli.mdx) and configure it to access your Okteto instance. You also need an IDE with remote development over SSH.

## The Okteto Manifest of the Workspace

Create an empty folder for the configuration of the workspace:

```bash
mkdir remote-workspace
cd remote-workspace
```

Add an `okteto.yaml` file:

```yaml title="okteto.yaml"
dev:
  workspace:
    autocreate: true
    metadata:
      annotations:
        dev.okteto.com/inject-token: "true"
    image: ghcr.io/okteto/golang:1
    command: bash
    remote: 2222
    workdir: /workspace
    sync:
      - .:/workspace
```

Add a `.stignore` file that excludes every file from [File Sync](application-environments/develop/index.mdx#file-sync):

```text title=".stignore"
*
```

Each field configures one part of the workspace:

- [`autocreate`](reference/okteto-manifest.mdx#autocreate-bool-optional) makes `okteto up` create a Deployment named `workspace`, so the Okteto Manifest needs no `deploy` section.
- The `dev.okteto.com/inject-token` annotation, set under [`metadata`](reference/okteto-manifest.mdx#metadata-object-optional), makes Okteto inject the `OKTETO_CONTEXT` and `OKTETO_TOKEN` environment variables into the container. The Okteto CLI inside the container uses them to authenticate with your Okteto instance as the owner of the Namespace, with no `okteto context` setup.
- [`remote`](reference/okteto-manifest.mdx#remote-integer-optional) sets the local SSH port to `2222`.
- [`workdir`](reference/okteto-manifest.mdx#workdir-string-optional) sets the working directory of the container to `/workspace`, where `okteto up` opens its shell.
- [`sync`](reference/okteto-manifest.mdx#sync-string-required) is mandatory. With the `.stignore` file, it transfers no files, but `/workspace` is still backed by the persistent volume of the Development Container, so the repository you clone there survives `okteto down` and later `okteto up` sessions. `okteto down -v` deletes it.

## Starting the Development Container

Start the Development Container from the `remote-workspace` folder:

```bash
okteto up
```

`okteto up` opens a shell in the container. Leave it running, and run the next commands in that shell.

Install the Okteto CLI in the container:

```bash
curl https://get.okteto.com -sSfL | sh
```

:::tip
Everything you install outside `/workspace` is lost when the Development Container restarts, so you would install the Okteto CLI again on every `okteto up`. Build it into your own [development image](application-environments/develop/index.mdx#development-images) instead, with the other tools your remote session needs, such as debuggers, linters, and the backend of your IDE:

```dockerfile
FROM ghcr.io/okteto/golang:1
RUN curl https://get.okteto.com -sSfL | sh
```
:::

## Cloning and Deploying the Repository

Clone the repository:

```bash
git clone https://github.com/okteto/go-getting-started.git
```

To clone a private repository over SSH, mount your SSH key with the [`secrets`](reference/okteto-manifest.mdx#secrets-string-optional) field of the Development Container, and trust the host key of your Git provider before you clone. Okteto stores the files of the `secrets` field in a Kubernetes Secret in your Namespace, so use a key you're comfortable storing in the cluster:

```yaml title="okteto.yaml"
secrets:
  - $HOME/.ssh/id_ed25519:/root/.ssh/id_ed25519:400
```

```bash
ssh-keyscan github.com >> ~/.ssh/known_hosts
git clone git@github.com:<org>/<repo>.git
```

Deploy the application from the cloned repository. `okteto deploy` uses the injected credentials, and deploys the application environment in your Namespace:

```bash
cd go-getting-started
okteto deploy
```

## Connecting Your IDE

`okteto up` adds the `workspace.okteto` host to your `~/.ssh/config` file, and any IDE with remote development over SSH can open a project through it. Leave `okteto up` running, because it keeps the SSH tunnel open, and point your IDE at the host:

- **Visual Studio Code:** install the [Remote - SSH](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-ssh) extension, run **Remote-SSH: Connect to Host** from the Command Palette, and select `workspace.okteto`.
- **JetBrains IDEs:** open [JetBrains Gateway](https://www.jetbrains.com/remote-development/gateway/), select **Connect via SSH**, and create a connection with the user `root`, the host `localhost`, the port of the host entry, and the private key `~/.okteto/id_ecdsa_okteto`. Gateway installs the IDE backend you select inside the container.

Then open the `/workspace/go-getting-started` folder. The connection stays up while `okteto up` is running. If you stop it, run `okteto up` again and reconnect.
