Volume Snapshots let you initialize persistent volume claims with the contents of an existing Volume Snapshot.
Use them to work with large datasets, or to create application environments with real data from your production or staging environments.

## Requirements

Volume Snapshots need a CSI driver that supports snapshots, and a `VolumeSnapshotClass` for that driver.

### CSI Driver Installation

Volume Snapshots work with any CSI-compliant driver, such as:
- [Google Compute Engine Persistent Disk CSI Driver](https://cloud.google.com/kubernetes-engine/docs/how-to/persistent-volumes/gce-pd-csi-driver)
- [Amazon EBS CSI driver](https://docs.aws.amazon.com/eks/latest/userguide/ebs-csi.html)
- [DigitalOcean Block Storage CSI Driver](https://github.com/digitalocean/csi-digitalocean)

Follow your vendor's instructions to install and set up the driver.

### VolumeSnapshotClass

Create a `VolumeSnapshotClass` in your cluster to set the CSI driver and the `deletionPolicy` for your `VolumeSnapshots`. For example:

<Tabs
  defaultValue="aws-ebs"
  values={[
    { label: 'Amazon EBS', value: 'aws-ebs', },
    { label: 'GCE Persistent Disk ', value: 'gce-pd', },
    { label: 'DigitalOcean Block Storage', value: 'do', },
  ]}
>
<TabItem value="aws-ebs">

```yaml
# okteto-snapshot-class.yaml
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshotClass
metadata:
  name: okteto-snapshot-class
driver: ebs.csi.aws.com
deletionPolicy: Delete
```

</TabItem>
<TabItem value="gce-pd">

```yaml
# okteto-snapshot-class.yaml
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshotClass
metadata:
  name: okteto-snapshot-class
driver: pd.csi.storage.gke.io
deletionPolicy: Delete
```

</TabItem>

<TabItem value="do">

```yaml
# okteto-snapshot-class.yaml
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshotClass
metadata:
  name: okteto-snapshot-class
driver: dobs.csi.digitalocean.com
deletionPolicy: Delete
```

</TabItem>
</Tabs>

Save the manifest as `okteto-snapshot-class.yaml` and run the following command to create the `VolumeSnapshotClass`:

```bash
kubectl apply -f okteto-snapshot-class.yaml
```

### StorageClass (Optional)

You can also create a storage class for Okteto to use when it creates the volumes.

<Tabs
  defaultValue="aws-ebs"
  values={[
    { label: 'Amazon EBS', value: 'aws-ebs', },
    { label: 'GCE Persistent Disk ', value: 'gce-pd', },
    { label: 'DigitalOcean Block Storage', value: 'do', },
  ]}
>
<TabItem value="aws-ebs">

```yaml
# okteto-snapshot-sc.yaml
kind: StorageClass
apiVersion: storage.k8s.io/v1
metadata:
  name: okteto-snapshot-sc
provisioner: ebs.csi.aws.com
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer
```

</TabItem>
<TabItem value="gce-pd">

```yaml
# okteto-snapshot-sc.yaml
kind: StorageClass
apiVersion: storage.k8s.io/v1
metadata:
  name: okteto-snapshot-sc
provisioner: pd.csi.storage.gke.io
parameters:
  type: pd-standard
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer
```

</TabItem>
<TabItem value="do">

```yaml
# okteto-snapshot-sc.yaml
kind: StorageClass
apiVersion: storage.k8s.io/v1
metadata:
  name: okteto-snapshot-sc
provisioner: dobs.csi.digitalocean.com
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer
```

</TabItem>
</Tabs>

Save the manifest as `okteto-snapshot-sc.yaml` and run the following command to create the `StorageClass`:

```bash
kubectl apply -f okteto-snapshot-sc.yaml
```

## Enabling Volume Snapshots

To enable Volume Snapshots in your Okteto instance, add the following values to your `config.yaml` file and run a [Helm upgrade](self-hosted/manage/upgrade.mdx#upgrading-your-okteto-instance) to apply them.

The [`volumeSnapshots` Helm configuration](self-hosted/helm-configuration.mdx#volumesnapshots) lists every available setting.

<Tabs
  defaultValue="aws-ebs"
  values={[
    { label: 'Amazon EBS', value: 'aws-ebs', },
    { label: 'GCE Persistent Disk ', value: 'gce-pd', },
    { label: 'DigitalOcean Block Storage', value: 'do', },
  ]}
>
<TabItem value="aws-ebs">

```yaml
volumeSnapshots:
  enabled: true
  driver: ebs.csi.aws.com
  class:  okteto-snapshot-class
  storageClass: okteto-snapshot-sc
```

</TabItem>
<TabItem value="gce-pd">

```yaml
volumeSnapshots:
  enabled: true
  driver: pd.csi.storage.gke.io
  class:  okteto-snapshot-class
  storageClass: okteto-snapshot-sc
```

</TabItem>
<TabItem value="do">

```yaml
volumeSnapshots:
  enabled: true
  driver: dobs.csi.digitalocean.com
  class:  okteto-snapshot-class
  storageClass: okteto-snapshot-sc
```

</TabItem>
</Tabs>

By default, every user in your cluster can use any available snapshot as a data source for their application environments. To restrict this, set the `enableNamespaceAccessValidation` key to `true` in the `volumeSnapshots` section of the configuration.
