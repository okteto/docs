The GitHub integration uses a GitHub App to give your developers access to private GitHub repositories. With it:

- Your users select a repository from a list, instead of typing the full repository URL.
- Everyone in your cluster gets read-only access to private repositories.
- You control access to Okteto and to the repositories for the whole organization, or per repository.
- Pipelines use an app-scoped token instead of a shared SSH key.

## Configuration Steps

Setting up the GitHub integration takes steps in GitHub and in your Okteto instance. In GitHub:

1. [Create the GitHub App](#creating-the-github-app)
1. [Generate a private key for the GitHub App](#generating-a-private-key-for-the-github-app)

In your Okteto instance:

1. [Add the GitHub App configuration to Okteto](#adding-the-github-app-configuration-to-okteto)
1. [Verify your installation](#verifying-your-installation)

Once you complete these steps, your Okteto instance authenticates with the GitHub App when it clones repositories in Okteto pipelines.

### Creating the GitHub App

1. In the upper-right corner of any page in GitHub, select your `profile icon > Organizations`.
1. Click the `settings` of the organization where you want to create the app.
1. In the left navigation, select `Developer settings > GitHub Apps`.
1. Select `New GitHub App`.
1. Fill in the following fields:
   - `GitHub App Name:` a name for your app (for example, `okteto-$YOUR_GITHUB_ORGANIZATION`)
   - `Homepage URL:` https://okteto.$SUBDOMAIN
   - `Callback URL:` https://okteto.$SUBDOMAIN/auth/callback?origin=github (required if you use GitHub as your authentication provider)
1. Uncheck the `Expire user authorization tokens` option.
1. Check the `Request user authorization (OAuth) during installation` option.
1. In the `Post Installation` section, check the `Redirect on update` option.
1. In the `Webhook` section, uncheck the `Active` option.
1. In the `Repository permissions` section, set the `Contents` permission to `Read-only`.
1. In the `Organization permissions` section, set the `Members` permission to `Read-only`.
1. In the `Account permissions` section, set the `Email addresses` permission to `Read-only`.
1. In the `Where can this GitHub App be installed?` section, select the `Any account` option. This lets your users install the app in their own GitHub accounts and deploy their personal repositories in your Okteto instance.
1. Click the `Create GitHub App` button.
1. On the next screen, copy the `App Id` and `Client Id` values. You add them to your Okteto configuration in [Adding the GitHub App Configuration to Okteto](#adding-the-github-app-configuration-to-okteto).

GitHub's developer guide covers [creating a GitHub App](https://docs.github.com/en/developers/apps/building-github-apps/creating-a-github-app) in more detail.

### Generating a private key for the GitHub App

After you create the GitHub App, generate a client secret and a private key to authenticate to it:

1. In the upper-right corner of any page in GitHub, select your `profile icon > Organizations`.
1. Click the `settings` of the organization where you created the app.
1. In the left navigation, select `Developer settings > GitHub Apps`.
1. Select the GitHub App.
1. In the `Client secrets` section, click the `Generate a new client secret` button. Copy the value and save it somewhere safe: GitHub doesn't display it again. You add it to your Okteto configuration in [Adding the GitHub App Configuration to Okteto](#adding-the-github-app-configuration-to-okteto).
1. In the `Private keys` section, at the bottom of the page, click the `Generate a private key` button. A file with the private key is saved to your computer.

### Adding the GitHub App Configuration to Okteto

Add the values you generated in GitHub to your Helm configuration file:

```yaml
github:
  enabled: true
  appId: "${YOUR_APP_ID}"
  clientId: ${YOUR_CLIENT_ID}
  clientSecret: ${YOUR_CLIENT_SECRET}
  installationUrl: https://github.com/apps/${YOUR_GITHUB_APP_NAME}/installations/new
  appPrivateKey: |
    -----BEGIN RSA PRIVATE KEY-----
    ......
    .....
    -----END RSA PRIVATE KEY-----
```

> You can also store the `clientSecret` and the `appPrivateKey` in a [secret](self-hosted/helm-configuration.mdx#store-sensitive-configuration-values-using-a-secret).

- `clientID` and `clientSecret` are the values of the GitHub App you created.
- `appPrivateKey` is the private key you generated.

> If you use GitHub as your [authentication provider](self-hosted/install/auth/github.mdx), you can also use your GitHub App's `appId` and `clientId` values in the `auth.github` section of your Helm configuration file.

After you update your Helm configuration file, run the following command to reconfigure your Okteto instance:

```bash
helm upgrade okteto okteto/okteto -f config.yaml --namespace=okteto
```

For a new installation, run the following command instead:

```bash
helm install okteto okteto/okteto -f config.yaml --namespace=okteto
```
