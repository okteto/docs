# Setting up certificates with AWS ACM

Okteto can use certificates issued by or imported into AWS Certificate Manager (ACM).

## Requirements

You need the following CLI installed on your machine:

- `aws` >= 2.15 ([AWS CLI installation guide](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html#getting-started-install-instructions))

You also need the Load Balancer Controller in your Kubernetes cluster.
If it isn't installed yet, [create the Load Balancer Controller IAM Role](get-started/install/amazon-eks.mdx#create-load-balancer-controller-iam-role) and [deploy the Load Balancer Controller](get-started/install/amazon-eks.mdx#deploy-load-balancer-controller) to your Kubernetes cluster.

:::note
If you don't install the Load Balancer Controller, set the ALPN policy to `HTTP2Preferred` in the AWS NLB TLS listener on port 443.
:::

## Setting up environment variables

The following environment variables help you script the certificate configuration.

The [Okteto Domain](get-started/install/amazon-eks.mdx#a-domain-and-the-ability-to-create-wildcard-dns-records-for-it) of your Okteto installation:

```bash
export OKTETO_DOMAIN="<<your-okteto-domain>>"
```

Your AWS Region:

```bash
export AWS_REGION="$(aws configure get region)"
```

Disable AWS CLI pagination (optional):

```bash
export AWS_PAGER=""
```

## Create an AWS Route 53 DNS Zone

Okteto uses a DNS zone for its internal endpoints (for example, registry, kubernetes, buildkit) and for your application endpoints.
Create a DNS zone with the following command:

```bash
aws route53 create-hosted-zone \
    --name="${OKTETO_DOMAIN}" \
    --caller-reference="$(date +%s)"
```

From the output, note the following properties:

- `HostedZone.Id`: set it as the value of the following environment variable:
  
```bash
export HOSTED_ZONE_ID="<<your-hosted-zone-id>>"
```

- `DelegationSet.Nameservers[]`: use them to delegate the DNS zone from your domain's nameservers.

:::tip
You can retrieve your DNS zone's nameservers again with the following command:
```bash
aws route53 get-hosted-zone --id="${HOSTED_ZONE_ID}"
```
:::

## Request a Certificate Using AWS ACM with DNS Validation

Okteto requires a wildcard certificate that matches its DNS zone.
Request a certificate with the following command:


```bash
aws acm request-certificate \
    --domain-name="*.${OKTETO_DOMAIN}" \
    --validation-method="DNS" \
    --region="${AWS_REGION}"
```

From the output, note the following property:

- `CertificateArn`: it identifies the certificate in integrated AWS services.
  
```bash
export CERTIFICATE_ARN="<<your-certificate-arn>>"
```

## Publish the Validation Records to the DNS Zone

:::warning
Before you continue, make sure the DNS zone you created is authoritative and correctly delegated from your main domain.
:::

Get the validation records with the following command:

```bash
aws acm describe-certificate \
  --certificate-arn="${CERTIFICATE_ARN}" \
  --region="${AWS_REGION}" \
  --query='Certificate.DomainValidationOptions[0].ResourceRecord'
```

Create a change batch file and replace the highlighted values:

```json title="resource-record.json"
{
  "Comment": "Add a CNAME record for foo to point to bar.com",
  "Changes": [
    {
      "Action": "CREATE",
      "ResourceRecordSet": {
        // highlight-next-line
        "Name": "REPLACE ME WITH RESOURCE RECORD NAME",
        "Type": "CNAME",
        "TTL": 300,
        "ResourceRecords": [
          {
            // highlight-next-line
            "Value": "REPLACE ME WITH RESOURCE RECORD VALUE"
          }
        ]
      }
    }
  ]
}
```

Publish the validation records:

```bash
aws route53 change-resource-record-sets \
  --hosted-zone-id="${HOSTED_ZONE_ID}" \
  --change-batch=file://resource-record.json
```

Watch the status of the validation:

```bash
aws acm describe-certificate \
  --certificate-arn="${CERTIFICATE_ARN}" \
  --region="${AWS_REGION}" \
  --query='Certificate.DomainValidationOptions[0].ValidationStatus'
```

The status changes from `PENDING_VALIDATION` to `SUCCESS` when the validation completes.

:::tip
You can wait until your certificate is validated with the following command:

```bash
aws acm wait certificate-validated \
  --certificate-arn="${CERTIFICATE_ARN}" \
  --region="${AWS_REGION}"
```

The command polls the AWS API every 60 seconds and exits with code 255 after 40 failed attempts.
:::

## Configure Okteto to use your ACM Certificate

Add the following snippet to your Okteto Helm configuration file and replace the highlighted value:

```yaml title="config.yaml"
ingress-nginx:
  controller:
    service:
      annotations:
        service.beta.kubernetes.io/aws-load-balancer-type: "nlb"
        service.beta.kubernetes.io/aws-load-balancer-backend-protocol: "ssl"
        // highlight-next-line
        service.beta.kubernetes.io/aws-load-balancer-ssl-cert: "<<your-certificate-arn>>"
        service.beta.kubernetes.io/aws-load-balancer-ssl-ports: "https"
        service.beta.kubernetes.io/aws-load-balancer-scheme: "internet-facing" 
        service.beta.kubernetes.io/aws-load-balancer-alpn-policy: "HTTP2Preferred"
```

[Upgrade your Okteto instance](self-hosted/manage/upgrade.mdx) to apply the new configuration.
Upgrade to the same version you already run: it keeps the changes to a minimum and makes any issue easier to troubleshoot.

:::note
If you didn't install the Load Balancer Controller, set the ALPN policy to `HTTP2Preferred` in the AWS NLB TLS listener on port 443.
The [AWS documentation](https://docs.aws.amazon.com/elasticloadbalancing/latest/network/listener-update-certificates.html#update-alpn-policy) explains how to do it from the console or the AWS CLI.
:::
