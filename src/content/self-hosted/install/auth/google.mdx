Okteto can use Google as its authentication provider.

[Google's documentation](https://support.google.com/cloud/answer/6158849?hl=en) explains how to create an OAuth 2.0 Client.

## Prerequisites

- A working installation of [Okteto](get-started/install/index.mdx)
- [Helm](https://helm.sh/docs/intro/install/) 3.0+ installed on your local machine
- Access to a [Google account](https://cloud.google.com/) with permissions to create an OAuth 2.0 Client

## Create the OAuth 2.0 Client

When you create the OAuth 2.0 Client, provide the following values:

**Authorized javascript origin**:

```
https://okteto.DOMAIN
```

**Authorized redirect URIs**:

```
https://okteto.DOMAIN
https://okteto.DOMAIN/auth/callback
```

Copy the `Client Secret` value. You need it to configure Okteto.

## Configure Okteto

When the Google OAuth 2.0 Client is ready, update the `auth` section of your Helm configuration file with the following values:

```yaml title="config.yaml"
auth:
  google:
    enabled: true
    clientId: clientid.apps.googleusercontent.com
    // highlight-next-line
    clientSecret: "REPLACE_ME_WITH_YOUR_OAUTH_CLIENT_SECRET"
    allowDomains:
      - example.com
```

> You can also store the sensitive part of these credentials in a [Kubernetes secret](self-hosted/helm-configuration.mdx#store-sensitive-configuration-values-using-a-secret).

[Upgrade your Okteto instance](self-hosted/manage/upgrade.mdx) to apply the new configuration.
Upgrade to the same version you already run: it keeps the changes to a minimum and makes any issue easier to troubleshoot.

The `allowDomains` field is optional. When you set it, only users whose Google Workspace accounts match one of the listed domains can log in to your Okteto instance.
An empty `allowDomains` field lets any user with a valid Google Workspace account log in.
