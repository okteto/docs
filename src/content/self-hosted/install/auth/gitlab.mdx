# Use GitLab as your Authentication Provider

Okteto can use GitLab as its authentication provider.

[GitLab's OpenID Connect documentation](https://docs.gitlab.com/ee/integration/openid_connect_provider.html) has more details.

## Prerequisites

- A working installation of [Okteto](get-started/install/index.mdx)
- [Helm](https://helm.sh/docs/intro/install/) 3.0+ installed on your local machine
- Access to a [GitLab account](https://gitlab.com) with permissions to enable and configure OAuth and OpenID, on gitlab.com or on a self-hosted GitLab instance

:::note
The examples use `https://gitlab.com`. If you use a self-hosted GitLab instance, replace `gitlab.com` with your GitLab instance's URL.
:::

## Create the GitLab Application

Create a new OAuth application with the following values:

- Name: "okteto"
- Redirect URI: "https://okteto.${YOUR_DOMAIN}.com/auth/callback"
- Clear the `Confidential` checkbox
- Select the following scopes:
  - `openid`
  - `profile`
  - `email`

## Configure Okteto

When the GitLab application is ready, update the `auth` section of your Okteto Helm configuration file with the values you copied in [Create the GitLab Application](#create-the-gitlab-application):

```yaml title="config.yaml"
auth:
  openid:
    enabled: true
    // highlight-next-line
    clientId: $CLIENT_ID
    // highlight-next-line
    clientSecret: $CLIENT_SECRET
    endpoints:
      issuer: "https://gitlab.com"
      authorization: "https://gitlab.com/oauth/authorize"
    mapping:
      externalIDKey: email
```

> You can also store the `clientSecret` value [in a Kubernetes secret](self-hosted/helm-configuration.mdx#store-sensitive-configuration-values-using-a-secret).

[Upgrade your Okteto instance](self-hosted/manage/upgrade.mdx) to apply the new configuration.
Upgrade to the same version you already run: it keeps the changes to a minimum and makes any issue easier to troubleshoot.

After the upgrade completes, open your Okteto instance and click **Log In**. If the configuration is correct, Okteto authenticates users with GitLab.

## Customize the attributes that Okteto consumes

By default, Okteto uses the following attributes when it creates a user:

- `Name` as the user's display name.
- `Nickname` as the user's username.
- `Email` as the email. Addresses must contain only lowercase alphanumeric characters, '-', or '.'
- `Picture URL` for the user's profile picture.

If you don't use some of those values, or you want to change which attributes Okteto maps, set the `mapping` field inside the `openid` key in your Helm configuration file.

```yaml title="config.yaml"
auth:
  openid:
    enabled: true
    clientId: $CLIENT_ID
    clientSecret: $CLIENT_SECRET
    endpoints:
      issuer: "https://gitlab.com"
      authorization: "https://gitlab.com/oauth/authorize"
    mapping:
      externalIDKey: nickname
      nameKey: name
      emailKey: email
      pictureKey: picture
```

The value of every key in the `mapping` section must match a `claim` in your GitLab OpenID configuration, and it must contain a non-empty value. The `claims_supported` section of `https://gitlab.com/.well-known/openid-configuration` lists the available claims.
