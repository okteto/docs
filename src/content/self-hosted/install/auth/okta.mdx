Okteto can use Okta as its authentication provider.

[Okta's OpenID Connect documentation](https://developer.okta.com/docs/concepts/oauth-openid/) has more details.

## Prerequisites

- A working installation of [Okteto](get-started/install/index.mdx)
- [Helm](https://helm.sh/docs/intro/install/) 3.0+ installed on your local machine
- Access to an [Okta Workforce Identity Cloud account](https://www.okta.com) with permissions to create Applications

## Create the Okta Application

Create a new app integration, as shown in the following image:

  <Image

    alt="Create the new app"

</p>

Fill in the following values in the **New Web App Integration** window:

1. Name: The name of your app (for example, Okteto)
2. Grant type: authorization code
3. Sign-in redirect URIs: `https://okteto.{YOUR_DOMAIN}` and `https://okteto.{YOUR_DOMAIN}/auth/callback`
4. Assignments: create a dedicated group for Okteto (recommended), so you control from Okta who can access your instance

Leave the other values empty and click **Save**.

By default, Okteto uses the following attributes when it creates a user. Okteto syncs them when it creates the account and every time the user logs in.

- `Name` as the user's display name.
- `Nickname` as the user's username.
- `Email` as the email. Addresses must contain only lowercase alphanumeric characters, '-', or '.'
- `Picture URL` for the user's profile picture.

Authentication fails if the `Nickname` or `Email` property is missing or empty. [Customize the attributes that Okteto consumes](#customize-the-attributes-that-okteto-consumes) explains how to change the attributes Okteto uses for authentication and account creation.

Open `https://{YOUR_TENANT}.okta.com/.well-known/openid-configuration` and copy the `issuer` and `authorization_endpoint` values.

## Configure Okteto

When the Okta application is ready, update the `auth` section of your Okteto Helm configuration file with the values you copied in [Create the Okta Application](#create-the-okta-application):

```yaml title="config.yaml"
auth:
  openid:
    enabled: true
    // highlight-next-line
    clientId: $CLIENT_ID
    // highlight-next-line
    clientSecret: $CLIENT_SECRET
    endpoints:
      // highlight-next-line
      issuer: $ISSUER_URL
      // highlight-next-line
      authorization: $AUTHORIZATION_URL
    mapping:
      externalIDKey: email
```

[Customize the attributes that Okteto consumes](#customize-the-attributes-that-okteto-consumes) describes `mapping`.

For a sample Okta tenant, the configuration looks like this:

```yaml title="config.yaml"
auth:
  openid:
    enabled: true
    clientId: 0oa76rh0z5zgKG7XXXXX
    clientSecret: dTgsfHbYV9tt91Ng4dzvpULw6y7kjJaYxzfXXXXX
    endpoints:
      issuer: https://dev-6093102.okta.com
      authorization: https://dev-6093102.okta.com/oauth2/v1/authorize
    mapping:
      externalIDKey: email
```

> You can also store the `clientSecret` value [in a Kubernetes secret](self-hosted/helm-configuration.mdx#store-sensitive-configuration-values-using-a-secret).

[Upgrade your Okteto instance](self-hosted/manage/upgrade.mdx) to apply the new configuration.
Upgrade to the same version you already run: it keeps the changes to a minimum and makes any issue easier to troubleshoot.

After the upgrade completes, open your Okteto instance and click **Log In** to log in with Okta.

## Customize the attributes that Okteto consumes

By default, Okteto uses the following attributes when it creates a user:

- `Name` as the user's display name.
- `Nickname` as the user's username.
- `Email` as the email. Addresses must contain only lowercase alphanumeric characters, '-', or '.'
- `Picture URL` for the user's profile picture.

If you don't use some of those values, or you want to change which attributes Okteto maps, set the `mapping` field inside the `openid` key in your Helm configuration file.

```yaml title="config.yaml"
auth:
  openid:
    enabled: true
    clientId: $CLIENT_ID
    clientSecret: $CLIENT_SECRET
    endpoints:
      issuer: $ISSUER_URL
      authorization: $AUTHORIZATION_URL
    mapping:
      externalIDKey: nickname
      nameKey: name
      emailKey: email
      pictureKey: picture
```

The value of every key in the `mapping` section must match a `claim` in your Okta + OpenID configuration, and it must contain a non-empty value.

For example, to use the email instead of the nickname as the username, use the following configuration:

```yaml
auth:
  openid:
    enabled: true
    clientId: 0oa76rh0z5zgKG7XXXXX
    clientSecret: dTgsfHbYV9tt91Ng4dzvpULw6y7kjJaYxzfXXXXX
    endpoints:
      issuer: https://dev-6093102.okta.com
      authorization: https://dev-6093102.okta.com/oauth2/v1/authorize
    mapping:
      externalIDKey: email
```

## Troubleshooting

### Log in fails with a 500 error

The most likely cause is that the user isn't assigned to the application. Make sure the user (or their group) is assigned to the Okteto application in Okta.

To fix it, go to **Applications → Okteto → Assignments** and add the users or groups.
