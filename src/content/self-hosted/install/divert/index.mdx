Divert needs a service mesh in each shared environment and a few Okteto Helm values. The service mesh routes the calls between the services of the shared environment, and sends the requests that carry a divert header to the diverted services. Admins configure it once per cluster, and developers then use Divert from their Okteto Manifest, as described in [Using Divert](development/divert/index.mdx).

## Requirements

- Okteto 1.37 or later, and Okteto CLI 3.12 or later
- A service mesh that routes east-west traffic, the calls between services, by the `baggage` header. The cluster gateway controller routes the requests that enter through the endpoints of the shared environment, but it doesn't see the calls between services inside it
- The service mesh enabled in each **shared environment**, with sidecar injection or ambient mode. Diverted environments don't need it: their pods resolve service names to the shared environment when a service isn't deployed in them

:::tip Traffic through the cluster gateway controller
If the services in your shared environment always call each other through the cluster gateway controller, it's enough to add the cluster gateway controller to the service mesh. This is the case when services call each other by their public endpoints, and those hostnames resolve inside the cluster to the private IP of the cluster gateway controller, so the calls stay in the cluster and go through the gateway controller instead of an external load balancer.
:::

## Gateway API

If your service mesh implements the [Gateway API](https://gateway-api.sigs.k8s.io/), such as [Linkerd](https://linkerd.io/), enable Divert in your Okteto Helm values:

```yaml
divert:
  enabled: true
```

Okteto routes diverted traffic with Gateway API `HTTPRoute` resources in the shared environment, so the Gateway API CRDs (`v1`) must be installed in the cluster. Developers don't set any driver in their Okteto Manifest.

## Istio VirtualServices

If your service mesh is Istio and your applications use VirtualServices, enable VirtualServices in your Okteto Helm values instead. You don't need to set `divert`:

```yaml
virtualServices:
  enabled: true
```

Okteto routes diverted traffic by modifying the VirtualServices of the shared environment. Developers set `driver: istio` and the VirtualServices to divert in their Okteto Manifest.

## Shared Environments Outside Okteto

A shared environment in a namespace that Okteto doesn't manage is only supported with Istio VirtualServices. Select the namespace with `virtualServices.namespaceSelector`:

```yaml
virtualServices:
  enabled: true
  namespaceSelector:
    kubernetes.io/metadata.name: staging
```

Enable the service mesh in that namespace too.

## Network Policies

If you enable [`networkPolicies`](self-hosted/helm-configuration.mdx#networkpolicies), allow traffic between the shared environment and the diverted environments:

```yaml
networkPolicies:
  enabled: true
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              dev.okteto.com: "true"
```
