# Air-Gapped Network Environments<TiersList tiers="Enterprise Self-Hosted" />

Okteto Self-Hosted runs in air-gapped environments, isolated networks without internet access: you install, configure, and use your Okteto instance entirely offline. [Talk to us](https://www.okteto.com/contact/) if you want us to guide you during the installation.

## Step 1: Disabling Okteto Telemetry

By default, Okteto sends [telemetry data](self-hosted/helm-configuration.mdx#telemetry) to help us understand usage patterns and prioritize improvements.
In an air-gapped environment, disable telemetry by adding the following to your Okteto Helm configuration:

```yaml
telemetry:
  enabled: false
```

With telemetry disabled, the Okteto CLI doesn't send any usage analytics.

## Step 2: Setting Up a Private Registry for Required Images

By default, the images that deploy the Okteto Platform, and the images that the Okteto CLI uses, are hosted in GitHub Container Registry (`ghcr.io`).
In an air-gapped environment, you host these images in your private registry.

### Pushing Images to Your Private Registry

For simplicity, we recommend keeping the same repository names and tags in your private registry.

:::info
Okteto doesn't support `imagePullSecrets`, so configure your Kubernetes cluster to access your private registry beforehand.
:::

**Required Images for Okteto Platform Installation**

Push the following images to your private registry for the Okteto Chart installation:

- **ghcr.io/okteto/backend:{variables.chartVersion}**
- **ghcr.io/okteto/frontend:{variables.chartVersion}**
- **ghcr.io/okteto/buildkit:{variables.chartVersion}** or **ghcr.io/okteto/buildkit:{variables.chartVersion}-rootless**
- **ghcr.io/okteto/registry:{variables.chartVersion}**
- **ghcr.io/okteto/pipeline-runner:{variables.chartVersion}** or **ghcr.io/okteto/pipeline-runner:{variables.chartVersion}-rootless**
- **ghcr.io/okteto/daemon:{variables.chartVersion}**
- **ghcr.io/okteto/agent:{variables.chartVersion}**
- **ghcr.io/okteto/ingress-nginx-chroot:{variables.chartVersion}**
- **ghcr.io/okteto/reloader:{variables.chartVersion}**
- **ghcr.io/okteto/redis:{variables.chartVersion}**

For each Okteto CLI version, push the following images to your private registry:

- **ghcr.io/okteto/okteto:{variables.cliVersion}**

:::info
For Okteto Chart {variables.chartVersion}, we recommend requiring Okteto CLI {variables.cliVersion} on your developers' machines to reduce maintenance overhead.
:::

## Step 3: Updating the Helm Configuration

Once your images are in your private registry, update your Okteto Helm configuration so Okteto pulls the required images from it during deployment.

Replace `<<your-registry-url>>` with the hostname or IP address of your private registry, for example `my-registry.example.com:5000`. It must be accessible within your air-gapped environment and use the correct protocol (https) and port.

```yaml
globals:
  registry: <<your-registry-url>>

cli:
  image:
    registry: <<your-registry-url>>

ingress-nginx:
  controller:
    image:
      registry: <<your-registry-url>>

okteto-nginx:
  controller:
    image:
      registry: <<your-registry-url>>

reloader:
  global:
    imageRegistry: <<your-registry-url>>
```


## Step 4: Installing or Upgrading Okteto

Run the following command to install Okteto for the first time, or to upgrade an existing instance:

<CodeBlock language="bash">
  {`helm upgrade --install okteto okteto/okteto -f config.yaml --namespace=okteto --create-namespace --version=${variables.chartVersion}`}
</CodeBlock>


## Step 5: Installing the Okteto CLI

Install the Okteto CLI on your machine and on the machine of every developer on your team who uses Okteto.

#### Downloading the Okteto CLI

Download the binary of the Okteto CLI for your operating system from the [Okteto CLI {variables.cliVersion} release](https://github.com/okteto/okteto/releases/tag/{variables.cliVersion}), the version that matches your Okteto instance.

- On Linux and macOS, the binary is named `okteto`
- On Windows, the binary is named `okteto.exe`

#### Setting Up the Okteto Configuration Directory

Create a `.okteto` folder in your `$HOME` directory. The CLI stores its runtime configuration and dependencies there.

```bash
mkdir -p $HOME/.okteto
```

#### Downloading and Configuring Syncthing

Okteto uses [Syncthing](https://syncthing.net/) to synchronize files between your local machine and your Development Containers.
Download the Syncthing binary from its official releases page:

<CodeBlock language="bash">
  {`https://github.com/syncthing/syncthing/releases/tag/v${variables.syncthingVersion}`}
</CodeBlock>

- Uncompress the downloaded file
- Move the `syncthing` binary (`syncthing.exe` on Windows) to your `$HOME/.okteto` folder

#### Setting Executable Permissions (Linux and macOS Only)

On Linux and macOS, give executable permissions to both `okteto` and `syncthing`:

```bash
chmod +x okteto
chmod +x $HOME/.okteto/syncthing
```

:::note
### Browser Compatibility

The Okteto UI is supported on:
- **Google Chrome**: Last 8 versions
- **Mozilla Firefox**: Last 8 versions
- **Microsoft Edge**: Last 8 versions
- **Safari**: Last 2 major versions (macOS only)

Make sure every user in your air-gapped environment has access to one of these browsers to avoid compatibility issues.
:::
