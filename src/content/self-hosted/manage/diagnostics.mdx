Okteto provides a diagnostics tool built on the [Replicated Troubleshoot](https://troubleshoot.sh) framework. The tool is optional, but it helps troubleshoot complex issues, especially when Okteto Support is assisting you.

Since Okteto 1.16, the Helm installation deploys an `okteto-support-bundle` ConfigMap in the `okteto` namespace with the specs to create a support bundle.

## Installation

The `support-bundle` utility from Replicated Troubleshoot runs on your machine. It's packaged as a `kubectl` plugin and distributed through the [krew](https://github.com/kubernetes-sigs/krew/) package manager. Install krew by following its [installation guide](https://krew.sigs.k8s.io/docs/user-guide/setup/install/).

:::note
Run `kubectl krew` to check the installation, and make sure `krew` is in your `$PATH`, as the installation guide describes.
:::

Once krew is installed, install the `kubectl` plugin:

```bash
kubectl krew install support-bundle
```

The [Troubleshoot installation instructions](https://troubleshoot.sh/docs/#installation) have more details.

## Support bundle

The support bundle is a gzipped tarball with cluster information, logs for the Okteto components, and other relevant information. It helps troubleshoot issues with the cluster, especially during an incident where Okteto Support is assisting you. To create it, run:

```bash
kubectl support-bundle \
  --interactive=false \
  --debug \
  -n okteto \
  --load-cluster-specs
```

The bundle's default file name is `support-bundle-TIMESTAMP.tar.gz`. To change it, add `-o <filename>`. The [support bundle documentation](https://troubleshoot.sh/docs/support-bundle/introduction/) describes the command and its other arguments.
