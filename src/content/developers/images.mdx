Development images allow you to configure the runtime of your Development Containers.
Instead of having to keep a wiki with a never-ending list of tools, dependencies, and scripts to install and run, you can pack all of it in the development images of your Development Containers.

## Creating a development image

At a high level, a development image is a Docker container image that contains:

- One or more language runtimes (for example, python, ruby, node)
- SDKs for your language runtime (for example, JDK, python-dev)
- Binary dependencies (for example, openssl, git)
- Tools to manage and install dependencies (for example, pip, bundler, yarn)
- Tools to run your tests and analyze your code (for example, nosetest, pylint)
- Your source code

Build your development image in the [build](application-environments/okteto-manifest.mdx#build) section of the Okteto Manifest, and set it in the `image` key of your Development Container with the [OKTETO_BUILD_XXX](application-environments/okteto-variables.mdx#built-in-environment-variables-for-images-in-okteto-registry) variables.

Follow [Docker's best practices](https://docs.docker.com/develop/develop-images/dockerfile_best-practices/) and these recommendations:

- Pin all your dependencies, so there aren't any surprises
- Keep the Dockerfile in your repository, next to your code
- When using [multi-stage builds](https://docs.docker.com/develop/develop-images/multistage-build/), use your builder stage to build your development image
