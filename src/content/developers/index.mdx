Developers deploy their own [application environment](application-environments/index.mdx) with `okteto deploy`, from the same Okteto Manifest that pull requests and coding agents use. To code against it, `okteto up` turns a service of the environment into a Development Container: you edit the code locally with your own tools, and Okteto syncs every change to the container in the cluster, where hot reload and your debugger pick it up. The environment where you work in this way is your Development Environment.

The Okteto CLI finds how to deploy your application in an [Okteto Manifest](application-environments/okteto-manifest.mdx) (`okteto.yaml` or `.okteto/okteto.yaml`), or in a [Docker Compose](reference/docker-compose.mdx) file (`okteto-compose.yaml`, `docker-compose.yaml`, or `compose.yaml`). Use the `-f` flag of any command to point it to another file. To install the Okteto CLI, see [Install the Okteto CLI](get-started/install-okteto-cli.mdx), and see the [Okteto CLI reference](reference/okteto-cli.mdx) for every command.

- [Development Containers](developers/containers/index.mdx): how `okteto up` replaces a service with a Development Container, and guides for each language.
- [Development Images](developers/images.mdx): build an image with the tools you need in your Development Container.
- [File Synchronization](developers/file-synchronization.mdx): how `okteto up` keeps your local folder and your Development Container in sync, and how to ignore files.
- [SSH Server](developers/ssh-server.mdx): the SSH server that `okteto up` runs in your Development Container, to open a shell or connect your IDE.

To open a Development Container from your IDE over SSH, follow the [Connect your IDE](/tutorials/connect-your-ide/) tutorial.
