The Okteto Manifest (`okteto.yaml`) is a file in your repository that defines how to build, deploy, test, and develop your application. Developers, pull requests, and coding agents create their application environments from it, so they all build, deploy, and test the application the same way. This minimal Okteto Manifest builds two images, deploys them with Helm, and runs the end-to-end tests:

```yaml title="okteto.yaml"
build:
  api:
    context: api
  frontend:
    context: frontend

deploy:
  image: alpine/helm:4.3.2
  commands:
    - name: Helm Install
      command: |
        helm upgrade --install movies chart \
          --set api.image=${OKTETO_BUILD_API_IMAGE} \
          --set frontend.image=${OKTETO_BUILD_FRONTEND_IMAGE}

test:
  e2e:
    image: mcr.microsoft.com/playwright:v1.65.1-noble
    context: e2e
    commands:
      - bash run_tests.sh
```

This page explains each section of the Okteto Manifest with an example. The [Okteto Manifest reference](reference/okteto-manifest.mdx) covers every option.

## Build

The `build` section defines the images for your services. The [Okteto Build Service](application-environments/build-service.mdx) builds them inside the cluster:

```yaml
build:
  api:
    context: api
  frontend:
    context: frontend
```

Okteto builds one image from the `api` folder and another from the `frontend` folder. Your deploy commands reference them through the `OKTETO_BUILD_API_IMAGE` and `OKTETO_BUILD_FRONTEND_IMAGE` variables. See the [`build` reference](reference/okteto-manifest.mdx#build-object-optional) for every option.

## Dependencies

The `dependencies` section lists other Git repositories that Okteto deploys along with your application:

```yaml
dependencies:
  mongodb:
    repository: https://github.com/okteto/mongodb
    wait: true
```

Okteto deploys the `okteto/mongodb` repository using that repository's own Okteto Manifest, and waits for it to be ready before deploying your application. See the [`dependencies` reference](reference/okteto-manifest.mdx#dependencies) for every option.

## Deploy

The `deploy` section lists the commands that deploy your application, typically `helm` or `kubectl` commands:

```yaml
deploy:
  image: alpine/helm:4.3.2
  commands:
    - name: Deploy PostgreSQL
      command: helm upgrade --install postgresql postgresql/chart
    - name: Deploy the Movies app
      command: |
        helm upgrade --install movies chart \
          --set api.image=${OKTETO_BUILD_API_IMAGE} \
          --set frontend.image=${OKTETO_BUILD_FRONTEND_IMAGE}
```

Okteto runs the commands in order, inside the cluster, in a container started from the `image` you set, with [Remote Execution](application-environments/remote-execution.mdx). Every resource they create shows up in the Okteto UI as part of the application environment, and Okteto serves its endpoints over HTTPS. The commands can also create cloud resources, such as a managed database or a queue, with the [Cloud Credentials](admin/cloud-credentials/index.mdx) that your Admin configures. See the [`deploy` reference](reference/okteto-manifest.mdx#deploy-string-optional) for every option.

## Test

The `test` section defines the tests that Okteto Test runs against your application:

```yaml
test:
  unit:
    image: golang:1.26
    commands:
      - go test ./...
```

`okteto test` runs each test inside the cluster, in a container started from its `image`, against the application environment. See [Okteto Test](application-environments/okteto-test.mdx) for how tests run, and the [`test` reference](reference/okteto-manifest.mdx#test-object-optional) for every option.

## Destroy

The `destroy` section lists the commands that delete the resources your application uses outside the cluster:

```yaml
destroy:
  image: hashicorp/terraform:1.17.2
  commands:
    - name: Delete the cloud resources
      command: terraform destroy --auto-approve
```

`okteto destroy` runs these commands inside the cluster, in a container started from the `image` you set, and then deletes the Kubernetes resources of the application. Here, the commands delete the cloud resources that the deploy commands created with Terraform. See the [`destroy` reference](reference/okteto-manifest.mdx#destroy-string-optional) for every option.

## Dev

The `dev` section defines the Development Containers for your application:

```yaml
dev:
  api:
    command: bash
    sync:
      - api:/usr/src/app
```

`okteto up api` replaces the `api` service with a Development Container, syncs your local `api` folder to `/usr/src/app`, and opens a shell in it. Your changes run in the application environment as you save them. See [Development Containers](development-containers/index.mdx) for how `okteto up` works, and the [`dev` reference](reference/okteto-manifest.mdx#dev-object-optional) for every option.

## External

The `external` section lists the resources that are part of your application but run outside the cluster, such as cloud services or dashboards:

```yaml
external:
  lambda:
    icon: aws
    notes: docs/lambda.md
    endpoints:
      - name: function
```

The Okteto UI shows the `lambda` function alongside the rest of the environment, with its notes and its endpoint. This section only describes the resources. The commands in the [`deploy`](#deploy) and [`destroy`](#destroy) sections create and delete them. See the [`external` reference](reference/okteto-manifest.mdx#external-object-optional) for every option.
