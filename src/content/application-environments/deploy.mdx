`okteto deploy` creates or updates your application environment: it builds the images of your application, deploys its dependencies, and runs the commands in the `deploy` section of your Okteto Manifest. Developers, pull requests, and coding agents all run the same `okteto deploy`, with the same deploy commands, so the application deploys the same way for all of them.

## Deploy Commands

The `deploy` section lists the commands that deploy your application, typically `helm` or `kubectl` commands:

```yaml title="okteto.yaml"
deploy:
  image: alpine/helm:4.3.2
  commands:
    - name: Deploy PostgreSQL
      command: helm upgrade --install postgresql postgresql/chart
    - name: Deploy the Movies app
      command: |
        helm upgrade --install movies chart \
          --set api.image=${OKTETO_BUILD_API_IMAGE} \
          --set frontend.image=${OKTETO_BUILD_FRONTEND_IMAGE}
```

When you run `okteto deploy`, Okteto:

1. Builds the images of the [`build`](application-environments/build-service.mdx) section that changed since the last build, and pushes them to the Okteto Registry.
2. Deploys the repositories of the [`dependencies`](#dependencies) section that aren't deployed yet.
3. Runs the commands in order, inside the cluster, in a container started from the `image` you set, with [Remote Execution](reference/remote-execution.mdx). The machine that runs `okteto deploy` doesn't need Helm, `kubectl`, or any other tool your commands use.
4. Creates the [endpoints](application-environments/endpoints/automatic-ssl.mdx) of your application, and prints their URLs.

Your commands get the image that Okteto built for each service in an `OKTETO_BUILD_<NAME>_IMAGE` variable, next to the other [Okteto Variables](application-environments/okteto-variables.mdx#default-environment-variables). Every resource the commands create shows up in the Okteto UI as part of the application environment.

Your commands can deploy every service of the application, which gives you a full replica, or only the services that change, which gives you an Overlay Namespace: [Divert](application-environments/divert/index.mdx) routes its requests to a Shared Namespace that runs the rest of the application.

If your application runs images from a private registry, or the `image` of the `deploy` section is private, ask your Admin to configure [Registry Credentials](admin/registry-credentials/index.mdx), so Okteto can pull them.

To wait until every pod of the application is ready, add the `--wait` flag:

```bash
okteto deploy --wait
```

See the [`deploy` reference](reference/okteto-manifest.mdx#deploy-string-optional) for every option of the section, and the [`okteto deploy` reference](reference/okteto-cli.mdx#deploy) for every flag.

## Okteto Manifest Path and Name

`okteto deploy` uses the Okteto Manifest of the folder where you run it. To use another one, pass its path with the `-f` flag:

```bash
okteto deploy -f services/api/okteto.yaml
```

Each application environment has a name, which is the name of its repository, or of its folder, unless the [`name`](reference/okteto-manifest.mdx#name-string-optional) field of the Okteto Manifest or the `--name` flag sets another one. A Namespace can hold several application environments, each with its own name: for example, a monorepo with one Okteto Manifest for each application. You deploy, redeploy, and [destroy](application-environments/destroy.mdx) each one separately.

## Docker Compose

To deploy a Docker Compose file, set the `compose` field instead of a list of commands. Okteto translates the file into Kubernetes resources:

```yaml title="okteto.yaml"
deploy:
  compose: docker-compose.yml
```

If your repository has a Docker Compose file and no Okteto Manifest, `okteto deploy` deploys the Docker Compose file directly. See the [Docker Compose reference](reference/docker-compose.mdx) for the fields that Okteto supports.

## Dependencies {#dependencies}

The `dependencies` section lists other Git repositories that Okteto deploys along with your application, each with its own Okteto Manifest. Okteto deploys the dependencies in parallel. To order them, use `depends_on`: a dependency starts once the ones it lists have deployed successfully.

```yaml title="okteto.yaml"
dependencies:
  database:
    repository: https://github.com/okteto/database
  messaging:
    repository: https://github.com/okteto/messaging
  backend:
    repository: https://github.com/okteto/backend
    depends_on:
      - database
      - messaging
    wait: true
```

Here, `database` and `messaging` deploy at the same time, and `backend` starts when both are deployed. Because `backend` sets `wait: true`, your deploy commands don't start until `backend`, `database`, and `messaging` are deployed and healthy. Without `wait: true`, a dependency deploys at the same time as your deploy commands.

A dependency that's already deployed isn't deployed again, unless you run `okteto deploy --dependencies`. See the [`dependencies` reference](reference/okteto-manifest.mdx#dependencies) for every option, and the [Deploy a Multi-Repo Application with Dependencies](/tutorials/dependencies/) tutorial for a complete example.

## Deploying from the Okteto UI

You can also deploy an application environment from the Okteto UI, without the Okteto CLI. In the Namespace view, click **Deploy Dev Environment** and select where the application comes from:

- **Catalog:** an application from the [Catalog](admin/catalog.mdx) that your Admins maintain.
- **GitHub:** one of your GitHub repositories, after you connect your GitHub account in [**Settings > Integrations**](user-settings/integrations.mdx).
- **Git URL:** the URL of any Git repository. For a private repository that isn't on GitHub, use its SSH URL, and ask your Admin to add the [Okteto SSH key](admin/integrations.mdx#git-ssh-key) to your Git provider.

The dialog also takes the branch to deploy, the variables for your deploy commands, and the path of the Okteto Manifest, when it isn't at the root of the repository.

To let anyone deploy your repository with one click, add a [Develop on Okteto button](reference/develop-on-okteto-button.mdx) to its `README` file.
