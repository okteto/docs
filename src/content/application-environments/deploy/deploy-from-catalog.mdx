The Catalog lists the applications that your Admins preconfigured, each with its repository, branch, Okteto Manifest path, and variables. To deploy one, you pick it and click **Deploy**: you don't need to know where its Okteto Manifest is or which variables it needs. It's the same as running `okteto deploy --file <path> --var <name>=<value>` from a copy of the repository.

The Catalog shows up only when an Admin has added at least one item to it, in [**Admin > Catalog**](admin/catalog.mdx).

## Deploying a Catalog Item

1. In the Namespace view of the Okteto UI, click **Deploy Dev Environment**.
2. Select **Catalog** as the source, and select the application you want to deploy.
3. Optionally, change its branch, its variables, or its Okteto Manifest path, for example to deploy the branch of a feature or to set a variable for your environment.
4. Click **Deploy**.

Okteto builds and deploys the application in your current Namespace. The Namespace view shows it while it deploys, and its status changes to **Deployed** when it's ready.

See the [Okteto Manifest](application-environments/okteto-manifest.mdx) for how the repository defines its build, deploy, and test.

## Redeploying

To deploy the latest code of the branch, or to change the branch, the variables, or the Okteto Manifest path, click **Redeploy** next to the application, change what you need, and click **Redeploy**:

## Destroying

To destroy the application, click **Destroy** next to it and confirm. Okteto runs its `destroy` commands and deletes the resources it created, except its persistent volumes, unless you select **Include volumes**. You can't recover them afterwards, so back up any data you need first.
