Okteto deploys application environments from private Git repositories: from GitHub through the GitHub integration, and from any other Git provider over SSH.

## GitHub Private Repositories

To deploy your private GitHub repositories, connect your GitHub account in [**Settings > Integrations**](user-settings/integrations.mdx) and choose the repositories that Okteto can access. You can connect your personal repositories and your organizations' repositories to the same Okteto account.

:::note
An Admin must set up the GitHub integration for your Okteto instance before you can connect your GitHub account. If the **Deploy** dialog doesn't offer **GitHub** as a source, ask your Admin to [set up the GitHub integration](self-hosted/install/github.mdx).
:::

Once you connect your account, the **Deploy** dialog lists your public and private repositories when you select **GitHub** as the source. A lock icon marks the private ones.

<Image
  src={require("@site/static/img/private-repositories-list+1.42.png").default}
  alt="Deploy dialog listing GitHub repositories, with a lock icon next to the private ones"
  width="650"
/>

Select a repository and a branch, and click **Deploy**. Okteto clones the repository and deploys it with its [Okteto Manifest](application-environments/okteto-manifest.mdx). If a repository is missing from the list, click **Configure GitHub** to give Okteto access to it.

## Other Private Repositories

Okteto deploys private repositories from any other Git provider over SSH. Use the repository's SSH URL, both in the [**Deploy**](application-environments/deploy/deploy-from-git.mdx) dialog of the Okteto UI, with **Git URL** as the source, and with the [`okteto pipeline deploy`](reference/okteto-cli.mdx#pipeline) command in your terminal:

<Image
  src={require("@site/static/img/private-repository+1.42.png").default}
  alt="Deploy dialog with Git URL as the source and an SSH repository URL entered"
  width="676"
/>

To let Okteto clone the repository over SSH, an Admin adds the [Okteto SSH key](admin/integrations.mdx#git-ssh-key) to your Git provider.

:::note
Admins manage the trusted SSH hosts of every Git provider (GitHub, GitLab, Bitbucket, Azure DevOps, or a self-hosted provider) in [SSH Known Hosts](admin/ssh-known-hosts.mdx). Trusted hosts avoid host key verification failures in remote deploys and submodule operations.
:::
