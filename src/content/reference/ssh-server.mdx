`okteto up` runs an SSH server in your Development Container. The Okteto CLI uses it to run commands and forward ports between your machine and the Development Container, and you can use it to open a shell or connect your IDE.

When `okteto up` starts your Development Container, it:

- Injects a [minimal SSH server](https://github.com/okteto/remote) into the Development Container.
- Forwards a local port to port 22 of the Development Container.
- Adds a host entry for the Development Container to your local `~/.ssh/config` file:

```text title="~/.ssh/config"
Host MANIFEST_NAME.okteto
  HostName localhost
  Port PORT
  StrictHostKeyChecking no
  UserKnownHostsFile /dev/null
```

`okteto up` picks a random local port. To set it, use the [`remote`](reference/okteto-manifest.mdx#remote-integer-optional) field of your Okteto Manifest, or the `--remote` flag of `okteto up`.

## Connecting with SSH

While `okteto up` runs, connect to the Development Container with the local port:

```bash
ssh -p PORT localhost
```

Or with the host entry that `okteto up` added to your SSH config:

```bash
ssh MANIFEST_NAME.okteto
```

IDEs with remote development over SSH, such as [VS Code](https://marketplace.visualstudio.com/items?itemName=okteto.remote-kubernetes) or [PyCharm](https://www.jetbrains.com/help/pycharm/remote-debugging-with-product.html), connect to the same host entry. [Connecting your IDE](development/connect-your-ide.mdx) shows how to clone a repository in a Development Container and open it from your IDE over SSH.

## SSH Keys

The first time you run `okteto up`, the Okteto CLI creates an SSH key pair at `$HOME/.okteto/id_rsa_okteto` and `$HOME/.okteto/id_rsa_okteto.pub`. The SSH server in your Development Container only accepts connections authenticated with this key.
