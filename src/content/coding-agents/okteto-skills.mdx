The Okteto skills teach a coding agent how to work with Okteto: discover your services from `okteto.yaml`, deploy with `okteto deploy`, run your tests with `okteto test`, read the logs, and which commands it must never run. They're open source, in the [okteto/okteto-agent-skills](https://github.com/okteto/okteto-agent-skills) repository, and use the open [Agent Skills](https://agentskills.io) format, so the same skills work in Claude Code, Codex, Cursor, GitHub Copilot, and other compatible agents.

The skills need the [Okteto CLI installed](get-started/install-okteto-cli.mdx) and connected to your Okteto instance. Your project doesn't need an `okteto.yaml` yet: if it's missing, the `okteto-onboarding` skill creates one.

## Installing in Claude Code

Run these commands in Claude Code:

```bash
/plugin marketplace add okteto/okteto-agent-skills
/plugin install okteto
```

The first command registers the repository as a plugin marketplace, and the second installs the `okteto` plugin, with the skills, the `/dev-setup` and `/debug-env` commands, and the [guardrail hooks](#guardrail-hooks).

Claude Code doesn't update third-party plugins automatically. To get the latest version of the plugin, run:

```bash
/plugin marketplace update okteto-plugins
```

To update it automatically at startup instead, run `/plugin`, go to the **Marketplaces** tab, select `okteto-plugins`, and choose **Enable auto-update**.

To install and update the plugin for every developer in your organization, add the marketplace to Claude Code's [managed settings](https://code.claude.com/docs/en/settings#extraknownmarketplaces) with auto-update turned on:

```json
{
  "extraKnownMarketplaces": {
    "okteto-plugins": {
      "source": {
        "source": "github",
        "repo": "okteto/okteto-agent-skills"
      },
      "autoUpdate": true
    }
  },
  "enabledPlugins": {
    "okteto@okteto-plugins": true
  }
}
```

## Installing in Other Agents

The [`skills` CLI](https://github.com/vercel-labs/skills) installs the skills in Cursor, Codex, GitHub Copilot, Antigravity CLI (formerly Gemini CLI), and other compatible agents. It detects the agent you run it from:

```bash
npx skills add okteto/okteto-agent-skills
```

Agents that read a plain instruction file can use the files of the repository instead. They carry the same guidance, but load it on every turn instead of on demand:

```bash
# Agents that read AGENTS.md
cp agents/AGENTS.md <your-repo>/AGENTS.md

# GitHub Copilot
cp copilot/copilot-instructions.md <your-repo>/.github/copilot-instructions.md
```

Run these commands from a clone of the [okteto/okteto-agent-skills](https://github.com/okteto/okteto-agent-skills) repository. The `/dev-setup` and `/debug-env` commands and the guardrail hooks are only in the Claude Code plugin.

## Skills and Commands

| | What it does | When it activates |
|---|---|---|
| `okteto` skill | Teaches the agent the Okteto CLI: `okteto deploy`, `okteto build`, `okteto test`, `okteto logs`, and `okteto exec`, how to read the services from `okteto.yaml`, the autonomous and collaborative workflows, worktree isolation, and the cleanup rules. | The project has an `okteto.yaml`, or you mention Okteto. |
| `okteto-onboarding` skill | Discovers your services from Docker Compose files, Helm charts, Kubernetes manifests, or Dockerfiles, drafts an `okteto.yaml`, and validates it with `okteto validate`, `okteto build`, and `okteto deploy`. | The project has no `okteto.yaml`, and you ask to set it up for Okteto. |
| `okteto-debugging` skill | Triages an unhealthy environment with a playbook for each failure: `CrashLoopBackOff`, `OOMKilled`, `ImagePullBackOff`, `Pending`, runtime errors, deploy failures, and File Sync issues. Its diagnostics are read-only. | You describe an unhealthy service, or paste output that shows one. |
| `okteto-preview` skill | Deploys a Preview Environment for a branch or pull request with `okteto preview deploy`, gets its endpoints, and posts the URL on the pull request. It also covers Preview Environments in GitHub Actions and GitLab CI/CD. | You ask for a shareable environment or URL for a branch or pull request. |
| `okteto-manifest-optimizer` skill | Reviews an existing `okteto.yaml` for performance: pinned images, the ignore files of the build and sync contexts, cached dependencies, and resources. It then validates and redeploys it. | You ask to make your environment faster, or to review your `okteto.yaml`. |
| `/dev-setup` command | Validates the manifest, runs `okteto deploy --wait`, prints the endpoints of the environment, and guides you into `okteto up` for the service you pick. | You run it in Claude Code. |
| `/debug-env` command | Runs a read-only health check of the environment, and reports a root cause and a fix for each unhealthy service. Pass a service name to check only that one. | You run it in Claude Code. |

## Guardrail Hooks

The Claude Code plugin enforces the most important rules with hooks, even if the model forgets them:

- **`okteto up` is always denied.** It's interactive and hangs the agent's shell, so the agent asks you to run it.
- **`okteto destroy`, `okteto preview destroy`, and `okteto namespace delete` ask for your confirmation.** A pipeline that owns its environments, such as one that creates an environment per pull request, can allow them without confirmation by setting the `OKTETO_ALLOW_AGENT_DESTROY` environment variable to `1`. Don't set it on a developer's machine.
- **Sessions in an Okteto project start with a reminder.** When the repository has an `okteto.yaml`, the agent knows from the start that it's an Okteto project and that it has to verify its changes in an Okteto environment.

## Skill Activation

Skills load on demand: the agent matches the description of each skill against your prompt and what it has seen of the project. A prompt that mentions Okteto, or a session where the agent has already read `okteto.yaml`, activates the `okteto` skill. In Claude Code, the plugin's session hook gives the agent that signal from the start.

In other agents, a generic prompt such as "implement this feature" gives the agent no reason to use Okteto, so it may write the code and validate it locally, without deploying anything. To make verification in Okteto part of every task, add it to your repository's agent instructions file (`AGENTS.md` for most agents, `CLAUDE.md` for Claude Code):

```markdown
## Verifying changes

This project deploys to Okteto. After implementing any change, verify it in an
Okteto environment: deploy with `okteto deploy --wait` and run the tests
defined in `okteto.yaml` with `okteto test`. Use the okteto skill for all
environment work.
```

The instructions file loads in every session, so the agent treats verification in Okteto as part of done, even when the prompt never mentions Okteto.

## Example Prompts

What you ask the agent decides what it does:

| Prompt | What the agent does |
|---|---|
| "Set this repo up for Okteto." | Creates and validates an `okteto.yaml` (`okteto-onboarding` skill). |
| "I have `okteto up` running for the api service. Check the logs for errors and run the test suite." | Works inside your Development Container with `okteto exec` ([collaborative](coding-agents/collaborative-workflows.mdx)). |
| "The `/api/orders` endpoint returns a 500 on an empty cart. Investigate and fix it." | Debugs against your running environment ([collaborative](coding-agents/collaborative-workflows.mdx)). |
| "Deploy the environment, add a `/health` endpoint to the api service, run the tests, and open a PR." | Deploys, codes, tests, and opens the pull request ([autonomous](coding-agents/autonomous-workflows.mdx)). |
| "Pick up PROJ-123, implement it against a live environment, and open a PR when the tests pass." | Handles the whole ticket ([autonomous](coding-agents/autonomous-workflows.mdx)). |
| "My dev environment is slow to start. Review the manifest." | Reviews and rewrites `okteto.yaml` for performance (`okteto-manifest-optimizer` skill). |
