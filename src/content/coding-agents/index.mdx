Coding agents such as Claude Code, Codex, Cursor, and GitHub Copilot build, deploy, and test their changes in their own [application environment](application-environments/index.mdx), created from the same Okteto Manifest that developers and pull requests use. The agent calls the endpoints of the running application, runs your tests, and reads the logs, and it fixes what fails before it opens a pull request.

The agent's sandbox stays light. Builds, deployments, and tests run in the cluster through the Okteto CLI, so the sandbox needs the agent, Git access, and the Okteto CLI, but no Docker daemon and none of your application's dependencies:

The [Okteto skills](coding-agents/okteto-skills.mdx) teach the agent this workflow: which commands to run, which to never run, and how to discover your services from `okteto.yaml`.

- [Okteto Skills](coding-agents/okteto-skills.mdx): install the skills in Claude Code, Codex, Cursor, GitHub Copilot, or another agent, and make sure the agent uses them on every task.
- [Autonomous Workflows](coding-agents/autonomous-workflows.mdx): the agent takes a task from a ticket to a pull request, and deploys and tests in its own application environment.
- [Collaborative Workflows](coding-agents/collaborative-workflows.mdx): you run `okteto up`, and the agent works inside your Development Container with `okteto exec`.
- [Best Practices and Troubleshooting](coding-agents/best-practices.mdx): the command rules for agents, worktree isolation, cleanup, and fixes for common problems.

## Autonomous and Collaborative Workflows

An agent works in one of two ways, depending on whether you stay in the loop:

| | [Autonomous](coding-agents/autonomous-workflows.mdx) | [Collaborative](coding-agents/collaborative-workflows.mdx) |
|---|---|---|
| **Who drives** | The agent, end to end | You and the agent, together |
| **Started by** | A ticket, a webhook, or a CI pipeline | You, in your terminal or IDE |
| **Environment** | The agent runs `okteto deploy` in its own Namespace | You run `okteto up`, and the agent runs `okteto exec` in your Development Container |
| **Feedback loop** | Deploy, test, and fix until the tests pass | File Sync and hot reload |
| **Best for** | Ticket-to-pull-request automation, parallel tasks | Pair programming, interactive debugging |

In both workflows, the agent never runs `okteto up`: it's interactive, and it hangs the agent's shell. The [command rules](coding-agents/best-practices.mdx#command-rules) list what an agent may run.
