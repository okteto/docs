In a collaborative workflow, you and a coding agent work on the same application environment. You run `okteto up` to turn a service into a [Development Container](application-environments/develop/index.mdx), with hot reload and a debugger, and tell the agent what to change. The agent stops running the build, deploy, and test cycle, and only edits the code. [File Sync](application-environments/develop/index.mdx#file-sync) copies every file the agent edits to the Development Container within seconds, so you see the result of a change without rebuilding or redeploying.

## How It Works

1. You open a session with your coding agent, such as Claude Code, in your repository. With the [Okteto skills](coding-agents/okteto-skills.mdx), the agent creates the [Namespace of the session](coding-agents/index.mdx#parallel-tasks) and deploys the application environment in it with `okteto deploy --wait`.
2. In another terminal, you start the Development Container of the service you're working on, in the Namespace of the session. The agent never runs `okteto up` itself, because it's interactive:

   ```bash
   okteto up <service> -n <namespace>
   ```

3. From that moment, the agent stops building, deploying, and testing. It only edits the code on your machine: File Sync copies each change to the Development Container, and hot reload applies it to the running application.
4. You have the application on `localhost`, through the ports that the Development Container forwards. You check each change there, with your browser and your debugger, and ask the agent for the next one.
5. When you're done, you stop the Development Container with `okteto down <service> -n <namespace>`, and ask the agent to run the tests with `okteto test` and open the pull request.

## Hot Reload

This workflow depends on hot reload: the `command` of your Development Container must always start the application with a tool that reloads or restarts it when a file changes, such as `node --watch`, `air`, `uvicorn --reload`, or `dotnet watch`. Without it, the changes that the agent makes reach the Development Container, but the application keeps running the old code until someone restarts it. See [Development Containers](application-environments/develop/index.mdx) for how to set the `command`.
