In a collaborative workflow, you and a coding agent work on the same application environment. You run `okteto up` to turn a service into a [Development Container](development-containers/index.mdx), and the agent runs commands inside it with `okteto exec`. [File Sync](development-containers/file-synchronization.mdx) copies every file the agent edits to the Development Container within seconds, so the agent sees the result of a change without rebuilding or redeploying.

## How It Works

1. You, or the agent, deploy the environment with `okteto deploy --wait`.
2. You start the Development Container in your terminal:

   ```bash
   okteto up <service>
   ```

3. The agent edits the code on your machine, and File Sync copies the changes to the Development Container.
4. The agent runs commands in the Development Container with `okteto exec -- <command>`, and runs your tests with `okteto test <name>`.
5. You and the agent iterate until the task is done.

The agent never runs `okteto up` itself: it's interactive and hangs the agent's shell. With the [Okteto skills](coding-agents/okteto-skills.mdx), the agent asks you to run it.

The output of the service in your Development Container shows up in your `okteto up` terminal, not in `okteto logs`. The agent uses `okteto logs <service>` for the other services of the environment.

## Changes That Need a Rebuild

File Sync only copies what the running container reads at runtime. A change to anything baked into the image at build time doesn't reach the Development Container until you rebuild it:

- A `Dockerfile` or `.dockerignore` file.
- A dependency manifest, such as `go.mod`, `package.json`, `requirements.txt`, or `pom.xml`.
- `okteto.yaml`.

After one of these changes, the agent rebuilds the image and redeploys the application:

```bash
okteto validate        # only when okteto.yaml changed
okteto build <service>
okteto deploy --wait
```

## Example: Fixing a Bug

You start the Development Container for the `api` service:

```bash
okteto up api
```

And you ask the agent:

```text
The /api/orders endpoint returns a 500 error when the cart is empty.
Can you investigate and fix it?
```

The agent reproduces the failure, fixes the code, and checks the fix inside the Development Container:

```bash
# Reproduce the failure with the test that covers it
okteto exec -- npm test -- --grep "empty cart"

# After reading the code and fixing it, run the tests again
okteto exec -- npm test
```

File Sync copies the fix to the Development Container, so the agent runs the tests against the new code right away. If the service runs with hot reload, it also picks up the fix without a restart. See the [command rules](coding-agents/best-practices.mdx#command-rules) for every command an agent may run in this workflow.
