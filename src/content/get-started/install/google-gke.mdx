This guide explains how to install Okteto in Google Kubernetes Engine (GKE).

## Installation Requirements

Install these CLIs on your machine:

- `okteto` >= {variables.cliVersion} ([installation guide](get-started/install-okteto-cli.mdx))
- `kubectl` >= 1.28 ([installation guide](https://kubernetes.io/docs/tasks/tools/#kubectl))
- `helm` >= 3.14 ([installation guide](https://helm.sh/docs/intro/install/))

You also need:

- An Okteto license
- A domain where you can create wildcard DNS records
- A Kubernetes cluster

## Getting Your Okteto License

You need a license to install Okteto. If you have an Okteto subscription, your license key came with it, and [support](https://okteto.com/support) can send it again if you can't find it. If you don't have a subscription yet, [sign up for the free tier](https://www.okteto.com/free-tier/): you get a one-year license for up to 5 users and 500 environments per month, and you don't need a credit card.

## A Domain and the Ability to Create Wildcard DNS Records for It

You need enough access to a [subdomain](self-hosted/helm-configuration.mdx#subdomain), such as `dev.example.com`, to add a wildcard DNS record to it.
By default, Okteto exposes the endpoints of your application environments on that subdomain.

This guide uses [Google Cloud DNS](https://cloud.google.com/dns) for the DNS records, but any DNS service works.

## Deploy a Kubernetes Cluster

To create the cluster, follow Google's [GKE cluster creation guide](https://cloud.google.com/kubernetes-engine/docs/how-to/creating-a-cluster).

Okteto supports Kubernetes versions {variables.kubernetesMinVersion} through {variables.kubernetesMaxVersion}.
To get started, we recommend a Kubernetes cluster with this configuration:

- Kubernetes v{variables.kubernetesMaxVersion}
- A pool with at least 3 `n2-standard-4` nodes
- 250 GB per disk

## Installing Okteto

:::note
Argo CD installs the same Helm chart declaratively. See [Configure Argo CD](self-hosted/manage/argocd.mdx) for the `Application` manifest, sync policy, and the `ignoreDifferences` Okteto requires.
It replaces [Add the Okteto Helm repository](#add-the-okteto-helm-repository) and [Installing the Okteto Helm chart](#installing-the-okteto-helm-chart). Every other step on this page still applies, including the DNS record and the sign-in.
:::

You install Okteto with its Helm chart.

### Add the Okteto Helm Repository

Add the Okteto Helm repository:

```bash
helm repo add okteto https://charts.okteto.com
helm repo update
```

### Create the Helm Configuration File

Create a `config.yaml` file with these settings, replacing `license` and `subdomain` with your own values:

```yaml title="config.yaml"
// highlight-next-line
license: "REPLACE ME WITH YOUR OKTETO LICENSE"
// highlight-next-line
subdomain: "REPLACE ME WITH YOUR OKTETO DOMAIN"

registry:
  storage:
    filesystem:
      persistence:
        enabled: true
```

:::warning ARM Node Groups

GKE applies taints to ARM nodes automatically. If your GKE cluster uses ARM-based node groups, add these tolerations to your `config.yaml`:

```yaml
globals:
  tolerations:
    okteto:
      - key: "kubernetes.io/arch"
        operator: "Equal"
        value: "arm64"
        effect: "NoSchedule"
    dev:
      - key: "kubernetes.io/arch"
        operator: "Equal"
        value: "arm64"
        effect: "NoSchedule"
ingress-nginx:
  controller:
    tolerations:
      - key: "kubernetes.io/arch"
        operator: "Equal"
        value: "arm64"
        effect: "NoSchedule"
okteto-nginx:
  controller:
    tolerations:
      - key: "kubernetes.io/arch"
        operator: "Equal"
        value: "arm64"
        effect: "NoSchedule"
reloader:
  reloader:
    deployment:
      tolerations:
        - key: "kubernetes.io/arch"
          operator: "Equal"
          value: "arm64"
          effect: "NoSchedule"
```

The [ARM Support guide](self-hosted/manage/arm-support.mdx) covers the recommended cluster configuration, the supported instance types (Tau T2A), and the known limitations.

:::

This is the minimum configuration. The [Helm configuration](self-hosted/helm-configuration.mdx) lists every setting.

### Installing the Okteto Helm Chart

Install the Okteto Helm chart:

<CodeBlock language="bash">
  {`helm upgrade --install okteto okteto/okteto -f config.yaml --namespace=okteto --create-namespace --version=${variables.chartVersion}`}
</CodeBlock>

After a few seconds, Helm creates all the resources. The output looks like this:

```bash
Release "okteto" has been installed. Happy Helming!
NAME: okteto
LAST DEPLOYED: Thu Mar 26 18:07:55 2020
NAMESPACE: okteto
STATUS: deployed
```

### Retrieve the Ingress Controller IP Address

Use `kubectl` to get the address that GKE allocated to the NGINX ingress controller that Okteto installs:

```bash
kubectl get service -l=app.kubernetes.io/name=ingress-nginx,app.kubernetes.io/component=controller --namespace=okteto
```

The output looks like this:

```bash
NAME                              TYPE           CLUSTER-IP   EXTERNAL-IP     PORT(S)                                     AGE
okteto-ingress-nginx-controller   LoadBalancer   10.0.7.73    34.68.230.234   80:30795/TCP,443:32481/TCP,1234:30885/TCP   5m
```

Add the `EXTERNAL-IP` address to the DNS of your domain. In Google Cloud DNS, create an `A` record with the name `*`. We suggest a TTL of 1 minute.

### Sign In to Your Okteto Instance

:::warning

The default installation isn't meant for production. Once you finish your evaluation, and before you give your team access to your Okteto instance, configure [Okteto Registry storage with Google Cloud Storage](self-hosted/install/okteto-registry-storage/google-cloud-storage.mdx).

:::

Once the installation finishes, your Okteto instance is available at `https://okteto.SUBDOMAIN`. The default installation uses [token-based authentication](self-hosted/install/auth/token.mdx). The post-installation notes that Helm prints include the URL to log in to the Okteto UI with the token of the Admin user, and the command to configure the Okteto CLI with that token. To show the notes again, run:

```bash
helm get notes okteto --namespace=okteto
```

## Optional: Configure Access to Your Google Artifact Registry

You can give Okteto [access to your Google Artifact Registry](admin/registry-credentials/google-artifact-registry.mdx). Your Dockerfiles and your deployments can then use its private images without pull secrets.

## Deploy Your First App

Before you deploy your first app, configure a valid [wildcard certificate](self-hosted/install/certificates/index.mdx). The default installation uses a self-signed certificate, and the Okteto CLI and `okteto test` don't accept it.

With the certificate in place, [install the Okteto CLI](get-started/install-okteto-cli.mdx) and configure it with the command of the post-installation notes. Then deploy your first application with the [quickstart](get-started/quickstart.mdx).
