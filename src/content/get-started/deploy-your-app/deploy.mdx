The `deploy` section of the Okteto Manifest lists the commands that deploy your application. `okteto deploy` runs them against your Okteto Namespace.

This page uses the [Movies app](https://github.com/okteto/getting-started). Run the commands from the root of your clone of the repository, as described in the [requirements of the series](get-started/deploy-your-app/index.mdx#requirements).

## The `deploy` Section

The `deploy` section of the Movies app runs one command:

```yaml title="okteto.yaml"
deploy:
  image: alpine/helm:4.3.2
  commands:
    - name: Helm Install
      command: |
        helm upgrade --install movies chart \
          --set api.image=${OKTETO_BUILD_API_IMAGE} \
          --set frontend.image=${OKTETO_BUILD_FRONTEND_IMAGE}
```

The meaning of these fields is:

- `image`: the container image where the commands run. `okteto deploy` runs them with [Remote Execution](core/remote-execution.mdx), in a container of this image inside your cluster, so you don't need Helm on your machine. `alpine/helm` is a widely used image with the Helm CLI, pinned here to Helm 4.3.2 (the Helm project doesn't publish an official image). The image must include `/bin/sh` and every tool that the commands run.
- `commands`: the list of commands to run, in order.
- `name`: a label for the command in the output of `okteto deploy` and in the Okteto UI.
- `command`: the command to run. It installs the Helm chart of the `chart` folder as the `movies` release, with the images of the `build` section. `OKTETO_BUILD_API_IMAGE` and `OKTETO_BUILD_FRONTEND_IMAGE` hold the references of those images, as described in [Build](build.mdx#image-variables).

The Movies app uses Helm, but you can also deploy with [Docker Compose](reference/docker-compose.mdx) or with [any other tool](core/remote-execution.mdx#defining-your-own-image), setting `image` to an image that has it. For examples, see [How do I deploy with Docker Compose or tools other than Helm?](https://community.okteto.com/t/how-do-i-deploy-with-docker-compose-or-tools-other-than-helm/1495) in the Okteto Community forum.

## The Helm Chart

The [templates of the Helm chart](https://github.com/okteto/getting-started/tree/main/chart/templates) deploy the whole application in your Namespace:

- `frontend` and `api`: a Deployment and a Service for each service.
- `mongodb`: a Deployment with the official `mongo` image, its Service, a PersistentVolumeClaim for the data, and a ConfigMap with an init script that creates the `okteto` user. A readiness probe marks MongoDB as ready when it accepts connections.
- `seed`: a Job that loads the movies into MongoDB. It's a Helm hook, so Helm runs it after every install or upgrade and waits for it to complete.
- `movies`: the Ingress that exposes the `frontend` and `api` services, described in [Endpoints](endpoints.mdx).

The `api` service and the `seed` job connect to MongoDB through its Service, at the hostname `mongodb`.

## Deploying the Application

Deploy the Movies app:

```bash
okteto deploy --wait
```

```bash

 i  Okteto Smart Builds is skipping build of "api" because it's already built from cache.

 i  Endpoints available:

  - https://movies-cindy.okteto.example.com/api
 ✓  Development environment 'getting-started' successfully deployed
```

The `--wait` flag makes `okteto deploy` wait until the pods of the application are healthy. Okteto names the deployment `getting-started`, after the repository, and lists it in the Okteto UI with its resources.

Check the logs of the `api` service:

```bash
okteto logs api
```

```bash
 i  Using cindy @ okteto.example.com as context
+ api-7bb6c5fc9d-fs2qb › api
api-7bb6c5fc9d-fs2qb api Server running on port 8080.
```

`okteto logs` keeps following the logs. Press `Ctrl+C` to stop it.
