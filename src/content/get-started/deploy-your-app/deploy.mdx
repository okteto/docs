The `deploy` section of the Okteto Manifest lists the commands that deploy your application. `okteto deploy` runs them in your Okteto Namespace.

This page uses the [Movies app](https://github.com/okteto/getting-started). Run the commands from the root of your local copy, as described in the [requirements of the series](get-started/deploy-your-app/index.mdx#requirements).

## The `deploy` Section

The `deploy` section of the Movies app runs one command:

```yaml title="okteto.yaml"
deploy:
  image: alpine/helm:4.3.2
  commands:
    - name: Helm Install
      command: |
        helm upgrade --install movies chart \
          --set api.image=${OKTETO_BUILD_API_IMAGE} \
          --set frontend.image=${OKTETO_BUILD_FRONTEND_IMAGE}
```

These are its fields:

- `image`: the container image that runs the commands. `okteto deploy` runs them with [Remote Execution](application-environments/remote-execution.mdx), in a container inside your cluster, so you don't need Helm on your machine. The Helm project doesn't publish an official image, so the Movies app uses `alpine/helm`, a widely used image with the Helm CLI, pinned to Helm 4.3.2. Any image works, as long as it includes `/bin/sh` and every tool your commands run.
- `commands`: the list of commands to run, in order.
- `name`: the label of the command in the output of `okteto deploy` and in the Okteto UI.
- `command`: the command to run. Here, it installs the Helm chart in the `chart` folder as the `movies` release, with the images from the `build` section: `OKTETO_BUILD_API_IMAGE` and `OKTETO_BUILD_FRONTEND_IMAGE` hold their references, as described in [Build](build.mdx#image-variables).

The Movies app uses Helm, but you can deploy with [Docker Compose](reference/docker-compose.mdx) or with [any other tool](application-environments/remote-execution.mdx#defining-your-own-image): set `image` to an image that includes it. [How do I deploy with Docker Compose or tools other than Helm?](https://community.okteto.com/t/how-do-i-deploy-with-docker-compose-or-tools-other-than-helm/1495) in the Okteto Community forum has examples.

## The Helm Chart

The [templates of the Helm chart](https://github.com/okteto/getting-started/tree/main/chart/templates) deploy the whole application in your Namespace:

- `frontend` and `api`: a Deployment and a Service for each service.
- `mongodb`: a Deployment with the official `mongo` image, its Service, a PersistentVolumeClaim for the data, and a ConfigMap with an init script that creates the `okteto` user. A readiness probe marks MongoDB as ready when it accepts connections.
- `seed`: a Job that loads the movies into MongoDB. It's a Helm hook, so Helm runs it after every install or upgrade and waits for it to complete.
- `movies`: the Ingress that exposes the `frontend` and `api` services, described in [Endpoints](#endpoints).

The `api` service and the `seed` job connect to MongoDB through its Service, at the hostname `mongodb`.

## Deploying the Application

Deploy the Movies app:

```bash
okteto deploy --wait
```

## Endpoints

Okteto creates an [HTTPS endpoint](application-environments/endpoints/automatic-ssl.mdx) for every [Ingress](application-environments/endpoints/ingress.mdx) in your Namespace. If your application uses the Gateway API, it does the same for its [HTTPRoutes](application-environments/endpoints/httproutes.mdx). The Movies app defines one Ingress, `movies`, in `chart/templates/ingress.yaml`:

```yaml title="chart/templates/ingress.yaml"
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: movies
  annotations:
    dev.okteto.com/generate-host: "true"
spec:
  rules:
    - http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: frontend
                port:
                  number: 80
          - path: /api
            pathType: Prefix
            backend:
              service:
                name: api
                port:
                  number: 8080
```

The `dev.okteto.com/generate-host: "true"` annotation tells Okteto to generate the host of the Ingress under the [Okteto Subdomain](self-hosted/helm-configuration.mdx#subdomain), as `<ingress-name>-<namespace>.<okteto-subdomain>`. For the `movies` Ingress in the `cindy` Namespace of an instance whose subdomain is `okteto.example.com`, that's `movies-cindy.okteto.example.com`. Requests to `/` go to the `frontend` service, and requests to `/api` go to the `api` service.

If you deploy with Docker Compose, define your endpoints in the [`endpoints` section of your Docker Compose file](reference/docker-compose.mdx#endpoints-object-optional) instead.

`okteto deploy` prints the endpoints when it finishes. To list them at any time, run:

```bash
okteto endpoints
```

```bash

```
