Okteto builds, deploys, and tests your whole application in your Kubernetes cluster. All it needs is an [Okteto Manifest](application-environments/index.mdx), an `okteto.yaml` file at the root of your repository. Every developer and every AI agent gets their own copy of the application, with public HTTPS endpoints, and can run the tests against it. This series takes the [Movies app](https://github.com/okteto/getting-started), a sample application that already has a complete Okteto Manifest, through each of those steps. To do the same in your own repository, we recommend using an AI agent with the [Okteto agent skills](coding-agents/index.mdx).

If your application is defined in a Docker Compose file, follow [Develop a Docker Compose application with Okteto](/tutorials/compose-getting-started/) instead.

## Requirements

- Access to an Okteto instance. To install one, follow the [installation guide](get-started/install/index.mdx).
- The [Okteto CLI](get-started/install-okteto-cli.mdx) installed, with an Okteto Context configured for your Okteto instance.
- A local copy of the Movies app:

```bash
git clone https://github.com/okteto/getting-started
cd getting-started
```

Run every command in this series from the root of that folder, on the `main` branch. You don't need to edit any files, except to try hot reload in [Develop](develop.mdx).

## The Movies App

The Movies app has three services, deployed by the Helm chart in the `chart` folder:

- `frontend`: a React application, built with Vite, that lists movies.
- `api`: a Node.js API that reads the movies from MongoDB.
- `mongodb`: a MongoDB database that runs the official `mongo` image. A `seed` job loads the movies into it on every deployment.

## The Okteto Manifest

This is the `okteto.yaml` file of the Movies app:

```yaml title="okteto.yaml"
build:
  api-dev:
    context: api
    target: dev

  api:
    context: api
    target: prod
    depends_on:
      - api-dev

  frontend-dev:
    context: frontend
    target: dev

  frontend:
    context: frontend
    target: prod
    depends_on:
      - frontend-dev

deploy:
  image: alpine/helm:4.3.2
  commands:
    - name: Helm Install
      command: |
        helm upgrade --install movies chart \
          --set api.image=${OKTETO_BUILD_API_IMAGE} \
          --set frontend.image=${OKTETO_BUILD_FRONTEND_IMAGE}

test:
  frontend:
    image: ${OKTETO_BUILD_FRONTEND_DEV_IMAGE}
    context: frontend
    caches:
      - /root/.npm
    commands:
      - npm ci
      - npm test

  e2e:
    image: mcr.microsoft.com/playwright:v1.65.1-noble
    context: e2e
    caches:
      - /root/.npm
    commands:
      - bash run_tests.sh
    artifacts:
      - test-results
      - playwright-report

dev:
  api:
    image: ${OKTETO_BUILD_API_DEV_IMAGE}
    command: node --watch --inspect server.js
    sync:
      - api:/usr/src/app
    persistentVolume:
      enabled: false
    forward:
      - 9229:9229

  frontend:
    image: ${OKTETO_BUILD_FRONTEND_DEV_IMAGE}
    command: npm run dev
    sync:
      - frontend:/usr/src/app
    persistentVolume:
      enabled: false
```

Each page of the series covers one part of that file, in this order:

1. [Build](build.mdx): the `build` section, which builds the application and development images of the `frontend` and `api` services with `okteto build`.
2. [Deploy](deploy.mdx): the `deploy` section, which installs the Helm chart with `okteto deploy`, and the public HTTPS endpoints where Okteto serves the application.
3. [Inspect](inspect.mdx): a look at the pods, logs, and events of the application with `kubectl`.
4. [Test](test.mdx): the `test` section, which runs unit and end-to-end tests with `okteto test`.
5. [Develop](develop.mdx): the `dev` section, which lets `okteto up` replace the `api` or the `frontend` service with a Development Container that reloads your changes as you save them.

With the Okteto Manifest of the Movies app in your clone of the repository, you're ready to start. In the first step, [build the images of the Movies app](build.mdx) with `okteto build`.
