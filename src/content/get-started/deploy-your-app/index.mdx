The [Okteto Manifest](core/okteto-manifest.mdx), an `okteto.yaml` file at the root of a repository, tells Okteto how to build, deploy, and test an application. This series runs each of those steps on the [Movies app](https://github.com/okteto/getting-started), a sample application with a complete Okteto Manifest.

## Requirements

- Access to an Okteto instance. To install one, follow the [installation guide](get-started/install/index.mdx).
- The [Okteto CLI](get-started/install-okteto-cli.mdx) installed, with an Okteto Context configured for your Okteto instance.
- A local copy of the Movies app:

```bash
git clone https://github.com/okteto/getting-started
cd getting-started
```

Run the commands of the series from the root of this folder, on the `main` branch. You don't need to edit any file.

## The Movies App

The Movies app has three services, deployed by the Helm chart in the `chart` folder:

- `frontend`: a React application that lists movies.
- `api`: a Node.js API that reads the movies from MongoDB.
- `mongodb`: a MongoDB database, with the official `mongo` image. A `seed` job loads the movies into it on every deployment.

## The Okteto Manifest

This is the `okteto.yaml` file of the Movies app:

```yaml title="okteto.yaml"
build:
  frontend:
    context: frontend

  api:
    context: api

deploy:
  image: alpine/helm:4.3.2
  commands:
    - name: Helm Install
      command: |
        helm upgrade --install movies chart \
          --set api.image=${OKTETO_BUILD_API_IMAGE} \
          --set frontend.image=${OKTETO_BUILD_FRONTEND_IMAGE}

test:
  frontend:
    image: node:26
    context: frontend
    caches:
      - yarn/.cache
      - node_modules
    commands:
      - npm install --global yarn
      - yarn install
      - yarn test

  e2e:
    image: mcr.microsoft.com/playwright:v1.65.1-noble
    context: e2e
    caches:
      - yarn/.cache
      - node_modules
    commands:
      - bash run_tests.sh
    artifacts:
      - test-results
      - playwright-report
```

Each page of the series covers one part of it, in this order:

1. [Build](build.mdx): the `build` section, which builds the images of the `frontend` and `api` services with `okteto build`.
2. [Deploy](deploy.mdx): the `deploy` section, which deploys the Helm chart, MongoDB included, with `okteto deploy`.
3. [Endpoints](endpoints.mdx): the Ingress of the Helm chart, which Okteto serves on public HTTPS endpoints.
4. [Test](test.mdx): the `test` section, which runs unit and end-to-end tests with `okteto test`.
