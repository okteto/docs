[Okteto Test](reference/okteto-cli.mdx#test) runs your tests in Test Containers inside your Okteto Namespace, next to the application you deployed with `okteto deploy`.
Test Containers use [Remote Execution](application-environments/remote-execution.mdx#how-remote-execution-works), so you don't need test runtimes on your machine, and your tests can reach the private services of your application.

The [`test`](reference/okteto-manifest.mdx#test-object-optional) section of the Okteto Manifest defines your Test Containers. The same `okteto test` command runs them from your machine and from your CI/CD pipeline, against a [Preview Environment](previews/index.mdx).

This page uses the [Movies app](https://github.com/okteto/getting-started), deployed with `okteto deploy` as described in [Deploy](deploy.mdx). Run the commands from the root of your local copy.

## Unit tests for the `frontend` service

The `frontend` Test Container runs the unit tests of the `frontend` service, written with [Vitest](https://vitest.dev/):

```yaml title="okteto.yaml"
test:
  frontend:
    image: ${OKTETO_BUILD_FRONTEND_DEV_IMAGE}
    context: frontend
    caches:
      - /root/.npm
    commands:
      - npm ci
      - npm test
```

`frontend` is the name of the Test Container. These are its fields:

- `image`: the image that runs the tests. It's the development image of the `frontend` service, built in the [`build` section](build.mdx), so the tests run with the same Node.js version as the [Development Container](develop.mdx).
- `context`: the folder that Okteto sends to the Test Container.
- `caches`: the folders that Okteto keeps between runs of the Test Container. `/root/.npm` is the npm cache, so later runs don't download the packages again.
- `commands`: the commands that run your tests. The Test Container fails if any of them exits with a non-zero code. `npm ci` installs the exact dependencies in `package-lock.json`, and `npm test` runs Vitest.

Run the `frontend` unit tests:

```bash
okteto test frontend
```

## End-to-end tests

The `e2e` folder contains [Playwright](https://playwright.dev/) tests that open the Movies app in a browser and compare the movies it shows with the data stored in MongoDB.
The `e2e` Test Container runs them:

```yaml title="okteto.yaml"
test:
  e2e:
    image: mcr.microsoft.com/playwright:v1.65.1-noble
    context: e2e
    caches:
      - /root/.npm
    commands:
      - bash run_tests.sh
    artifacts:
      - test-results
      - playwright-report
```

`mcr.microsoft.com/playwright:v1.65.1-noble` is the official Playwright image. It includes Node.js, npm, and the browsers of Playwright 1.65.1, the same version of `@playwright/test` that `e2e/package.json` pins. When you upgrade `@playwright/test`, change the image tag to match: each Playwright release only works with the browsers it was built for.

The `artifacts` field lists the files and folders that Okteto copies to your machine when the tests finish, in this case the Playwright results and the HTML report.

Run the end-to-end tests:

```bash
okteto test e2e
```

The Playwright report is now in the `e2e/playwright-report` folder on your machine.

Test Containers run inside your Okteto Namespace, which gives them two ways to reach your application:

- Public endpoints, built from the `OKTETO_NAMESPACE` and `OKTETO_DOMAIN` variables. The Playwright configuration [builds its `BASE_URL`](https://github.com/okteto/getting-started/blob/main/e2e/playwright.config.js#L3) this way.
- Private services, through the hostname `<service>.${OKTETO_NAMESPACE}`. The tests [connect to MongoDB](https://github.com/okteto/getting-started/blob/main/e2e/data/getStoredData.js#L5) at `mongodb.${OKTETO_NAMESPACE}`.

Run `okteto test` without arguments to run every Test Container in your Okteto Manifest.

Running `okteto deploy` and `okteto test` after each change is usually fast enough, especially when an AI agent writes and tests the code autonomously. With the [Okteto agent skills](coding-agents/index.mdx), the agent runs this loop in its own Namespace and reports back the tests it ran, the endpoints of the application, and a link to that Namespace.

The unit and end-to-end tests of the Movies app pass in your cluster. In the next step, [develop the Movies app in Development Containers](develop.mdx): `okteto up` reloads your changes in the `api` and `frontend` services as you save them.
