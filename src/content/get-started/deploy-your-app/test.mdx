[Okteto Test](reference/okteto-cli.mdx#test) runs your tests in Test Containers inside your Okteto Namespace, next to the Development Environment you deployed in the previous steps.
Test Containers use [Remote Execution](core/remote-execution.mdx#how-remote-execution-works), so you don't need to install test runtimes locally, and your tests can reach the private services of your application.

The [`test`](reference/okteto-manifest.mdx#test-object-optional) section of the Okteto Manifest defines your Test Containers. The same `okteto test` command runs them on your machine and in your CI/CD pipeline against a [Preview Environment](previews/index.mdx).

## Unit tests for the `frontend` service

Add the following Test Container to your `okteto.yaml` file to run the unit tests of the `frontend` service:

```yaml title="okteto.yaml"
test:
  frontend:
    image: node:20
    context: frontend
    caches:
      - yarn/.cache
      - node_modules
    commands:
      - yarn install
      - yarn test
```

`frontend` is the name of the Test Container. The meaning of the rest of the fields is:

- `image`: the image used as the runtime of your Test Container.
- `context`: the folder that Okteto sends to the Test Container.
- `caches`: a list of folders to persist between executions of the Test Container. Caches skip dependency installation on later runs.
- `commands`: a list of commands to execute your tests. The Test Container fails if any command exits with a non-zero code.

Create a `.oktetoignore` file in the `frontend` folder to exclude dependencies and cache metadata from the files sent to the Test Container:

```text title="frontend/.oktetoignore"
.yarn/cache
node_modules
```

Run the `frontend` unit tests:

```bash
okteto test frontend
```

## End-to-end tests

The `e2e` folder contains [Playwright](https://playwright.dev/) tests that open the Movies app in a browser and compare the movies it shows with the data stored in MongoDB.
Add the `e2e` Test Container to the `test` section, and create an `e2e/.oktetoignore` file with the same content as `frontend/.oktetoignore`:

```yaml title="okteto.yaml"
test:
  e2e:
    image: ghcr.io/okteto/playwright:chromium
    context: e2e
    caches:
      - yarn/.cache
      - node_modules
    commands:
      - bash run_tests.sh
    artifacts:
      - test-results
      - playwright-report
```

The `artifacts` field lists files and folders that Okteto exports to your local filesystem after the tests run, in this case the Playwright results and HTML report.

Run the end-to-end tests:

```bash
okteto test e2e
```

The Playwright report is now available in the `e2e/playwright-report` folder on your machine.

Test Containers run inside your Okteto Namespace, which gives them two ways to reach your application:

- Public endpoints, built from the `OKTETO_NAMESPACE` and `OKTETO_DOMAIN` variables. The Playwright configuration [builds its `BASE_URL`](https://github.com/okteto/getting-started/blob/main/e2e/playwright.config.js#L3) this way.
- Private services, through the hostname `<service>.${OKTETO_NAMESPACE}`. The tests [connect to MongoDB](https://github.com/okteto/getting-started/blob/main/e2e/data/getStoredData.js#L5) at `mongodb.${OKTETO_NAMESPACE}`.

Run `okteto test` without arguments to run every Test Container in your Okteto Manifest.
