The `build` section of the Okteto Manifest lists the container images of your application. `okteto build` builds them with the [Okteto Build Service](core/build-service.mdx), in your cluster, and pushes them to the [Okteto Registry](core/container-registry.mdx), so you don't need Docker on your machine.

This page uses the [Movies app](https://github.com/okteto/getting-started). Run the commands from the root of your clone of the repository, as described in the [requirements of the series](get-started/deploy-your-app/index.mdx#requirements).

## The `build` Section

The `build` section of the Movies app defines four images, two per service:

```yaml title="okteto.yaml"
build:
  api-dev:
    context: api
    target: dev

  api:
    context: api
    target: prod
    depends_on:
      - api-dev

  frontend-dev:
    context: frontend
    target: dev

  frontend:
    context: frontend
    target: prod
    depends_on:
      - frontend-dev
```

Each key is the name of an image. `context` is the folder that Okteto sends to the Build Service, and Okteto builds the `Dockerfile` of that folder. `target` selects a stage of the `Dockerfile`:

- `dev`: the development image. It contains Node.js, the dependencies that `npm ci` installs from `package-lock.json`, and the source code. The [Test](test.mdx) and [Develop](develop.mdx) pages run it.
- `prod`: the application image that the Helm chart deploys.

`depends_on` makes Okteto build the development image first, so the build of the application image reuses its cached layers. The `frontend/Dockerfile` builds the application in its `dev` stage, and its `prod` stage copies the result into an nginx image:

```dockerfile title="frontend/Dockerfile"
FROM node:26.13.1-trixie-slim AS dev

WORKDIR /usr/src/app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:1.30.7-alpine AS prod

COPY --from=dev /usr/src/app/dist /usr/share/nginx/html
EXPOSE 80
```

The [`build` reference](reference/okteto-manifest.mdx#build-object-optional) lists the other fields of an image, such as `dockerfile` and `args`.

## Building the Images

Build the four images:

```bash
okteto build
```

```bash
 i  Using cindy @ okteto.example.com as context
 i  Building '/Users/cindy/getting-started/api/Dockerfile'...
 ...
 ✓  Image 'registry.okteto.example.com/cindy/getting-started-api-dev:okteto' successfully pushed
 i  Building '/Users/cindy/getting-started/frontend/Dockerfile'...
 ...
 ✓  Image 'registry.okteto.example.com/cindy/getting-started-frontend-dev:okteto' successfully pushed
 i  Building '/Users/cindy/getting-started/api/Dockerfile'...
 ...
 ✓  Image 'registry.okteto.example.com/cindy/getting-started-api:okteto' successfully pushed
 i  Building '/Users/cindy/getting-started/frontend/Dockerfile'...
 ...
 ✓  Image 'registry.okteto.example.com/cindy/getting-started-frontend:okteto' successfully pushed
```

Okteto names each image after the repository and the image (`getting-started-api`), and pushes it to the Okteto Registry of your Namespace with the `okteto` tag. Run `okteto build api` to build only the `api` image.

Okteto skips the build of an image when its context hasn't changed since the last build ([Smart Builds](core/build-service.mdx#smart-builds)). In that case, `okteto build` prints:

```bash
 i  Okteto Smart Builds is skipping build of "api" because it's already built from cache.
```

To build the images again anyway, run `okteto build --no-cache`.

## Image Variables

After a build, Okteto sets an `OKTETO_BUILD_<IMAGE>_IMAGE` variable with the reference of each image, with dashes turned into underscores: `OKTETO_BUILD_API_IMAGE`, `OKTETO_BUILD_FRONTEND_IMAGE`, `OKTETO_BUILD_API_DEV_IMAGE`, and `OKTETO_BUILD_FRONTEND_DEV_IMAGE` for the Movies app. The `deploy` section passes the application images to Helm, so your application runs the images built from your local code, and the `test` and `dev` sections run the development images. The [built-in environment variables for images](core/okteto-variables.mdx#built-in-environment-variables-for-images-in-okteto-registry) list the other variables of each image.

`okteto deploy` also builds the images that aren't built yet, so you can deploy without running `okteto build` first.

The Okteto Registry now has the images built from your local code. In the next step, [deploy the Movies app](deploy.mdx) with those images.
