## What is containerization and Kubernetes?

Containers quickly became the norm for how we built and packaged our applications. [Containerization](https://aws.amazon.com/what-is/containerization/) of applications made the software delivery and development cycle easy by providing a convenient way to run applications anywhere - without having to worry about setting the environment up from scratch every time. But, to run our containerized applications in production, we still needed to solve a few pieces of the puzzle. And that's where Kubernetes came in to the picture.

## Problems With Containerization and Production Setups

Since [containerization became the norm](https://www.crowdstrike.com/cybersecurity-101/cloud-security/containerization/), we started having a separate container for each of our application microservice. But containers are meant to be ephemeral, and things can and do go wrong in production. This can lead to [containers going down unexpectedly](https://www.okteto.com/blog/how-to-speed-up-container-image-builds/). And this is just one of the many problems associated with containerization. Long story short, we couldn’t just run containers directly to serve our applications. We needed something to manage these running containers - a container orchestrator (like Kubernetes).

Managing a few containers to serve your application might still be possible with manual effort, but to run containers at scale, we needed some way to automate all the operational tasks associated with containerization. Container orchestrators like Kubernetes take care of all this. They are responsible for managing the complete container lifecycle and ensuring your applications are always up and running for users to access. They remove the manual effort of monitoring and managing containers by automating the whole process. Some of the tasks they generally take care of are:

- Deploying containers with the correct application images
- Monitoring provisioned containers and checking if they are healthy
- Scaling up or down the number of containers based on the application traffic
- Balancing load between different running containers using [services](https://www.okteto.com/blog/kubernetes-load-balancer-service/)

When it came to containerization, two prominent names appeared: [Docker Swarm](https://docs.docker.com/get-started/swarm-deploy/) and [Kubernetes](https://kubernetes.io/) (K8s). Let’s see how they differ and which one might be ideal for your use case.

## Docker Swarm vs Kubernetes

Containerization started a war between Docker Swarm and Kubernetes. Deciding between the two primarily depends on your use case. Docker Swarm is an easy to set up and maintain solution when you want to manage simple workloads. It has a lower learning curve and is lightweight. If you have a relatively simple application and don’t have the time to invest in a complex solution, Docker Swarm might be the better choice for you. Kubernetes, on the other hand, offers a lot more features and should be the choice if you want to run complex workloads at scale effectively. It has a lot larger open source community than Docker Swarm and is offered by all the major cloud providers. It also has a [vast ecosystem of tools](https://spacelift.io/blog/kubernetes-tools) built around it which extend its capabilities and make it the ideal choice for enterprises managing their microservices based applications. But the problem with Kubernetes is that it can be tough to learn and set up when getting started initially.

## How Kubernetes Helps With Containerized Applications

Now that you have an idea of why containerization with Kubernetes is helpful, you might be wondering how exactly does this work. K8s works on a declarative system to manage your containerized applications. You tell it how you want things configured by writing a YAML file, and then it will work towards bringing up all the required containers and other needed things.

Then it also continuously monitors the resources it has created and checks that they still match the state we had described in the configuration file. If that’s not the case, it takes the necessary actions required to get to that state. This is how [Kubernetes functions as a container orchestrator](https://www.okteto.com/blog/beginners-guide-to-kubernetes-deployments/) and avoids application downtime.
